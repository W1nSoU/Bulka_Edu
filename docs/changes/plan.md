# ПЛАН РЕФОРМУВАННЯ ТА РОЗШИРЕННЯ BULKA EDU BOT

> **Порядок виконання**: кожен етап виконується суворо зверху вниз. Перед початком кожного завдання обовʼязково залучається оптимальний суб-агент з `/Users/daniildusinskij/All/Dev/Bulka_Edu/.github/agents/`.

---

## 1. Посади та їх зберігання в базі даних

а) Перенесення посад із `bot/constants.py` до бази даних: створення таблиці `positions` в `users.db` з полями `id`, `name`, `days_count`, `created_at`.

б) Міграція при першому запуску: заповнення таблиці `positions` із поточного `AVAILABLE_ROLES`, з дефолтним `days_count = 5` для кожної посади. Сервер не зупиняється — міграція запускається автоматично при старті, якщо таблиця ще не існує.

в) Переприв'язка матеріалів: оскільки таблиця `materials` прив'язана до посади через текстовий рядок `role`, при перейменуванні посади виконується `UPDATE materials SET role = ? WHERE role = ?` — щоб матеріали не відв'язались. Це робиться автоматично при зміні назви.

г) Переприв'язка користувачів: поле `users.role` продовжує зберігати текст (для зворотної сумісності), але синхронізується через `positions.name`. Пряма зміна `position_id` — тільки якщо не ламає наявних даних.

д) Міграційний скрипт `tools/management/migrate_positions.py`: безпечний запуск на продакшн-сервері без втрати даних і без зупинки бота. Включає rollback-логіку на випадок помилки.

е) Зміна кількості навчальних днів для посади: нові дні зʼявляються у ВСІХ носіїв посади — і у поточних стажерів, і у тих хто вже пройшов навчання. Для вже пройшовших — додаткові блоки зʼявляються в меню «Навчання» без штрафних санкцій; людина отримуватиме нагадування в боті, але не видаляється з системи.

## 2. Навчальні матеріали — оновлений метод редагування

а) Функція «Вставити масив сторінок»: розширення кнопки «Вставити між сторінками» вибором режиму — «Одна сторінка» (поточна логіка) або «Масив сторінок» (FSM-цикл до команди «ГОТОВО»). Кількість сторінок у масиві — не обмежена.

б) При вставці масиву — перенумерація всіх наступних сторінок у базі: зсув `page_index` на +N для всіх записів, де `page_index > вставленої_позиції`.

в) Функція «Змінити сторінки» — доступна у **загальному меню редагування** матеріалу (окремий пункт, не під кожною сторінкою — для цього вже є кнопка «Виправити»). Запит діапазону → прийом нових сторінок поштучно у FSM-циклі.

г) Логіка зсуву після заміни: якщо нових сторінок більше ніж у діапазоні — посунути вправо, якщо менше — посунути вліво (перенумерація через UPDATE).

д) Після будь-якої зміни або вставки матеріалів — у боті зʼявляється запит до Dev/Адміністратора з кнопками: «Оголосити зараз», «Обʼєднати з наступним оголошенням», «Не оголошувати». Це дозволяє керувати хвилями оповіщень вручну.

## 3. Управління посадами через бот (Панель Адміністратора)

а) Нове меню «Посади» у розділі «Інше» Панелі Адміністратора: інлайн-кнопки з переліком усіх посад, пагінація по 6 на сторінку з кнопками «Наступна» / «Попередня».

б) Кнопка «Додати посаду»: FSM для введення назви нової посади та кількості днів навчання.

в) Картка посади: назва, кількість днів навчання, кількість активних працівників, кількість стажерів, кнопки «Змінити назву», «Змінити кількість днів», «Назад».

г) При зміні назви — автоматичний каскадний UPDATE у таблицях `materials`, `users`, `test_errors`, `training_events`.

д) Управління містами — також у розділі «Інше»: меню «Міста» з кнопками «Додати місто», «Видалити місто», «Змінити назву». Архітектура підтримує кількох Територіалів на одне місто.

## 4. Роль Територіал

а) Нова роль `Територіал` в `managers.db` (нове значення поля `process`). Повністю взаємодіє з ботом через свій Telegram-акаунт.

б) Дозволені функції Територіала: перегляд своїх керівників, стажерів, магазинів; управління керівниками свого міста. Заборонені: редагування матеріалів, відео, тестів, фото, змісту; токени; Health статус; аналітика; XLSX-звіти; Команда Адміністраторів.

в) Меню «Територіали» у Панелі Адміністратора: інлайн-список усіх Територіалів + кнопка «Додати». Картка Територіала: місто, ПІБ, кількість керівників/магазинів, кнопки «Керівники», «Змінити місто», «Видалити».

г) При додаванні нового Територіала до міста — запит Адміністратору: «Перенести всіх керівників цього міста до Територіала?». Якщо «Ні» — питання можна поставити повторно пізніше. Адміністратор також може в будь-який момент вручну перепривʼязати керівника до Територіала або назад до Адміністратора.

д) При видаленні Територіала — всі його керівники автоматично повертаються до Адміністратора без сповіщення.

е) Функція ручної перепривʼязки: в картці будь-якого керівника — кнопка «Перепривʼязати» для зміни відповідального (Адміністратор або конкретний Територіал).

## 5. Пошук та управління керівниками

а) Пошук у меню «Команда керівників»: пошук по ПІБ, прізвищу або Telegram ID — FSM-введення → відображення картки.

б) Картка керівника: ПІБ, tg_id, місто, магазин, кількість стажерів та працівників, відповідальний (Адміністратор або Територіал). Кнопки «Змінити», «Перепривʼязати», «Назад».

в) Меню «Змінити»: «Змінити магазин», «Змінити ПІБ», «Звільнити».

г) «Звільнити»: запис переводиться в статус «звільнений», Telegram ID деактивується (людина більше не має доступу до бота), але всі дані зберігаються в базі для аналітики та звітів.

д) Зміна магазину: при зміні магазину керівника — стажери та працівники старого магазину переходять під управління Територіала або Адміністратора тихо, без сповіщення. При додаванні нового керівника до магазину — запит: «Перевести всіх до нового керівника?».

---

## 6. Роль Наглядач

а) Нова роль `Наглядач` в `managers.db` — копія Адміністратора з урізаними правами. Додається виключно Адміністратором.

б) Наглядач БАЧИТЬ: аналітику в режимі читання (всі меню аналітики, без XLSX-звітів). Наглядач НЕ МОЖЕ: редагувати матеріали, відео, фото, тести, зміст; змінювати або видаляти працівників, стажерів, керівників; використовувати токени; переглядати Health статус; скачувати XLSX-звіти.

в) Меню «Наглядачі» у Панелі Адміністратора (розділ «Команда Bulka»): список Наглядачів, кнопка «Додати», картка з можливістю видалення.

## 7. Навчання для керівників

а) Кнопка «Навчання» доступна для всіх керівників постійно: доступ до перегляду матеріалів не зникає після завершення навчання.

б) Нова роль «Керівник Стажер»: при додаванні нового керівника — він одразу отримує і панель керівника (зі своїми стажерами), і блок «Навчання» за роллю «Керівник». Навчання веде Територіал.

в) Навчальні матеріали для ролі «Керівник» — інфраструктура закладається зараз (запис в `positions`, слот у `materials`), самі матеріали завантажуються через Панель Адміністратора пізніше.

г) Підтвердження завершення навчання: Територіал отримує запит про переведення «Керівник Стажер» → «Керівник».

## 8. Пагінація навчальних днів

а) Якщо кількість навчальних днів для посади > 6 — автоматичне розбиття на сторінки: по 6 днів на сторінку.

б) Кнопки «Наступна сторінка» / «Попередня сторінка» з позначкою поточної сторінки (наприклад, «Сторінка 1/3»).

## 9. Оповіщення про зміну навчальних матеріалів

а) Тригерний механізм: при будь-якій зміні або вставці у матеріали (текст, відео, фото, тести) — реєстрація події в новій таблиці `material_change_events`. Після кожної зміни Dev обирає режим розсилки (дивись пункт 2д).

б) Охоплення: хвиля розсилки охоплює 100% носіїв відповідної посади — незалежно від того, на якому дні навчання зараз знаходиться людина. Також отримують керівники.

в) Хвильова розсилка: розподіл отримувачів пачками по 40 осіб, наступна хвиля через 1 годину (APScheduler/asyncio).

г) Формат повідомлення: перелистування сторінок (якщо їх кілька). На останній сторінці — кнопка «Зі змінами ознайомлений/а». Після натискання кнопка замінюється текстом «Ви ознайомлені зі змінами». Матеріали залишаються доступними для повторного перегляду через меню «Навчання».

д) Аналітика ознайомлення: нове меню «Ознайомлення» у розділі «Аналітика» Панелі Адміністратора. Вибір «Керівники» / «Працівники» / «Стажери». Дати змін у вигляді інлайн-кнопок (пагінація > 6). Зберігається не більше 3 місяців.

е) Перегляд за датою: що змінено, список тих хто ознайомився (за магазинами з пагінацією), список тих хто не ознайомився.

є) Порогова логіка: «Не ознайомленим» вважається користувач через 72 години після надсилання. Якщо натиснув після 72 годин — потрапляє до ознайомлених з міткою годинника. Аналітика формується лише після 75 годин.

## 10. Панель Адміністратора — перейменування та реструктуризація

а) Перейменування скрізь у коді та інтерфейсі: «Dev» → «Адміністратор», «Dev-панель» → «Панель Адміністратора», «Команда Dev» → «Команда Адміністраторів».

б) Нова структура меню «Панель Адміністратора» по категоріях:
   - **Навчальні матеріали** — Матеріали, Відео, Тести, Фото, Змісти, Нагадати тему.
   - **Аналітика** — всі меню аналітики + XLSX-звіт (Наглядач бачить без XLSX).
   - **Команда Bulka** — Користувачі, Команда Керівників, Команда Адміністраторів, Територіали, Наглядачі.
   - **Інше** — Токени, Health статус, Посади, Міста, та решта кнопок.

в) Фото-заголовки: до кожного меню додається відповідне зображення з папки `img/admin/`. Фото до конкретних меню узгоджуються з власником перед початком цього етапу.
