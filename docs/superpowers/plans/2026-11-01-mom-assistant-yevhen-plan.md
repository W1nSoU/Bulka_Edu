## Огляд Проекту

Створення автономного, мінімалістичного Telegram-бота «Євген» для Ірини Душинської (HRD у «Булка маркет»). Бот працює в особистих повідомленнях Telegram, підтримує текстові та голосові повідомлення, зв'язується з локальним рушієм Antigravity та повністю позбавлений технічного шуму, жаргону чи будь-яких згадок про розробників і налаштування.

---

## Фази Реалізації

### Фаза 1: Створення структури директорії та ізольованого середовища
- Створити каталог `/Users/daniildusinskij/All/Dev/Mom_Assistant` та підкаталоги `logs/`, `tests/`.
- Створити `.gitignore` для виключення секретів (`.env`), логів (`logs/`), тимчасових аудіофайлів (`*.ogg`, `*.wav`) та артефактів Python.
- Створити `requirements.txt` з мінімальними надійними бібліотеками (`requests`, `python-dotenv`).
- Створити `.env.example` та робочий `.env` із токеном бота (`9018042027:AAFqNdqD4tCxPiY2aAvQAf7kljq00oA8F_8`) та дозволеними користувачами (`1001226587,738460434`).

### Фаза 2: Конфігурація персони Євгена
- Створити `config.json` з чистим системним промптом помічника Євгена.
- Суворе дотримання вимог: жодних згадок імені «Данік», жодних технічних термінів чи натяків на розробників.
- Обрамлення контексту: турботливий, спокійний, зрілий помічник для Ірини (HRD мережі «Булка маркет»), звертання на «Ви».

### Фаза 3: Модуль обробки аудіо та голосових повідомлень (`voice_handler.py`)
- Завантаження голосових повідомлень `.ogg` (Opus) через Telegram Bot API.
- Автоматична перевірка наявності `ffmpeg` (`/opt/homebrew/bin/ffmpeg` або системний).
- Конвертація у 16kHz моно PCM WAV для швидкого розпізнавання.
- Механізм очищення тимчасових аудіофайлів після обробки.

### Фаза 4: Міст до Antigravity (`antigravity_bridge.py`)
- Реалізація функції `auto_heal_runtime_env()`:
  - Автоматичне виявлення активного порту Antigravity Language Server та валідного CSRF-токена.
  - Пошук активного `runtime_env.json` або сканування локальних сокетів.
- Функція формування запиту до `agentapi send-message`:
  - Додавання системної рамки персони Євгена.
  - Отримання відповіді в чистому текстовому вигляді.
  - Запасний варіант прямого формування відповіді при недоступності мосту.

### Фаза 5: Модуль відправки повідомлень у Telegram (`tg_reply.py`)
- Відправка повідомлень через Telegram Bot API (`sendMessage`).
- Безпечне розбиття довгих відповідей на частини (chunks <= 3900 символів).
- Спроба відправки з розміткою Markdown, у разі помилки валідації розмітки - автоматична повторна відправка чистим текстом.
- Індикація статусу `sendChatAction(action="typing")`.

### Фаза 6: Головний демон бота (`bot.py`)
- Реалізація HTTP Long-polling за допомогою чистого `requests`.
- Суворий фільтр:
  - Дозволені лише особисті повідомлення (`chat.type == "private"`).
  - Перевірка `from_user.id` за білим списком (`1001226587`, `738460434`).
  - Стороннім користувачам надсилається коротке чемне повідомлення про приватний доступ.
- Маршрутизація типів повідомлень: текст або голосове.
- Підтримка команди `/start` з теплим привітанням від Євгена.

### Фаза 7: Скрипти життєвого циклу (`start.sh`, `stop.sh`)
- `start.sh`:
  - Перевірка наявності Python 3 та встановлених залежностей.
  - Запуск через `caffeinate -s -i python3 bot.py` у фоні.
  - Запис логів у `logs/assistant.log` та збереження PID у `bot.pid`.
- `stop.sh`:
  - Безпечна зупинка процесу за PID.

### Фаза 8: Верифікація та тестування
- Модульний тест `tests/test_bridge.py`:
  - Перевірка валідності токена через метод `getMe`.
  - Перевірка списку дозволених ID.
  - Перевірка конвертації тестового аудіо через `ffmpeg`.
  - Перевірка відсутності заборонених слів (імені Даніка та технічних термінів) у `config.json`.
- Запуск бота та перевірка відправки вітального повідомлення або тестового діалогу від імені Даніка (`738460434`).
