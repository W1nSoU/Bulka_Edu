# Дизайн специфікація: Налаштування ліміту питань та валідація банку в атестації

**Дата:** 2026-09-12  
**Статус:** Схвалено користувачем  
**Тема:** Конфігурація кількості запитань на тест, валідація достатності банку питань та очищення логів алертів.

---

## 1. Мета та контекст

У системі корпоративної атестації адміністратор повинен мати можливість гнучко вказувати, скільки саме запитань міститиме тест для кожної нової хвилі (за замовчуванням популярні значення: 5, 10, 15, 20 або довільне число). Крім того:
1. Статус достатності запитань для посади в меню «Банк запитань» повинен відображати зелену позначку `✅`, починаючи з 5 питань (раніше було 15).
2. Перед запуском хвилі система зобов'язана суворо валідувати, чи містить банк питань щонайменше вказану кількість питань для кожної посади працівників обраних пекарень (або для посади «Керівник», якщо запускається сесія керівників). Якщо хоча б одна посада не має потрібної кількості питань, запуск блокується із детальним списком дефіцитних посад.
3. Коли питань у банку більше, ніж ліміт хвилі, для кожного учасника формується унікальна випадкова вибірка питань без повторень (random sample without replacement), а варіанти відповідей у кожному питанні також перемішуються.
4. Помилка `chat not found` при надсиланні Telegram-алертів перехоплюється й ігнорується, щоб не засмічувати консольні логи.

## 2. Архітектурні зміни та компоненти

### 2.1. База даних (`database/attestation.py`)
- **Схема `attestation_waves`**:
  - Додається стовпець `questions_count INTEGER DEFAULT 10`.
  - У метод `init_attestation_db()` додається міграція:
    ```sql
    ALTER TABLE attestation_waves ADD COLUMN questions_count INTEGER DEFAULT 10;
    ```
    (з обробкою `sqlite3.OperationalError` у разі повторного виклику).
  - Функція `create_wave(title, session_type, deadline_days, passing_score, created_by, questions_count=10)` зберігає `questions_count`.
- **Випадкова вибірка в `start_inline_attempt(...)`**:
  - Отримуємо всі доступні питання для посади учасника з `attestation_questions`.
  - Перемішуємо список запитань: `random.shuffle(all_questions)`.
  - Якщо `len(all_questions) > wave.questions_count`, беремо зріз `all_questions[:wave.questions_count]`.
  - Для кожного питання варіанти перемішуються: `random.shuffle(options)`.
  - Сформований перелік `question_ids` та перемішані варіанти зберігаються у `attestation_attempts` для забезпечення стабільності при навігації.

### 2.2. Інтерфейс та FSM у боті (`bot/menus/attestation.py`)
- **Відображення банку запитань (`dev_att_questions_menu_handler`)**:
  - Зміна порогу індикатора:
    - $\ge 5$ питань: `✅`
    - від 1 до 4 питань: `⚠️`
    - 0 питань: `❌`
- **Новий крок майстра створення хвилі (`AttestationStates.create_wave_q_count`)**:
  - Після введення назви хвилі бот пропонує обрати кількість питань:
    - Інлайн-кнопки: `[ 5 питань ]`, `[ 10 питань ]`, `[ 15 питань ]`, `[ 20 питань ]`
    - Кнопка: `[ ✏️ Ввести іншу кількість ]`
    - Кнопка: `[ ❌ Скасувати ]`
  - Обробка вибору:
    - Натискання пресету: запис у FSM `data['questions_count'] = count` і перехід до вибору пекарень/керівників.
    - Натискання кнопки введення: бот очікує числове повідомлення від адміністратора (валідація $1 \le N \le 100$).
- **Сувора валідація перед запуском хвилі**:
  - На екрані перегляду налаштувань хвилі та при натисканні `[ 🚀 Підтвердити і запустити ]`:
    - Визначаються всі унікальні посади, які беруть участь у хвилі (всі активні працівники обраних пекарень або посада «Керівник»).
    - Запитується кількість питань у банку для кожної з цих посад.
    - Якщо `count < wave_questions_count`:
      - Виводиться інформаційне попередження зі списком посад і їх кількістю питань:
        ```text
        ⚠️ Неможливо запустити атестацію!
        У банку недостатньо питань для обраних посад (потрібно: {required}):
        • ВВ Пекар: 1 з {required}
        • ВВ Бариста: 3 з {required}

        💡 Будь ласка, додайте питання в банк або зменшіть кількість питань у тесті.
        ```
      - Запуск блокується; надаються кнопки `[ 🔄 Змінити к-ть питань ]`, `[ 📚 Банк питань ]`, `[ ⬅️ Назад ]`.

### 2.3. Обробка логів та алертів (`bot/services/logger.py`)
- У функції/хендлері надсилання Telegram алертів перевіряти винятки:
  - Якщо в тексті помилки міститься `chat not found`, не викликати критичне падіння чи повторний алерт, а відправляти у debug-лог:
    ```python
    if "chat not found" in str(e).lower():
        logger.debug(f"Telegram alert chat not found: {e}")
    ```

## 3. План тестування та верифікації

1. **Юніт-тести (`tests/test_attestation_flow.py`)**:
   - Тест створення хвилі з довільною кількістю питань (`questions_count=5`).
   - Тест вибірки: якщо в банку 12 питань, а `questions_count=5`, спроба містить рівно 5 унікальних питань.
   - Тест захисту від запуску хвилі, якщо в банку недостатньо питань для посади.
   - Запуск повного набору тестів: `PYTHONPATH=. venv/bin/python -m unittest tests/test_attestation_flow.py`.
2. **Ручна перевірка**:
   - Відкриття меню «📚 Банк запитань» — перевірка зміни піктограми на `✅` для посад із $\ge 5$ питаннями.
   - Проходження візарду створення хвилі через кнопки пресетів та ручне введення.
