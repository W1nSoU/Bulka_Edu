# Design Document: 📰 Розсилка новин мережі («Новини»)

## 1. Загальний огляд та мета
Створення підсистеми **«📰 Новини»** у розділі **«📨 Розсилки»** панелі керування.
Підсистема призначена для інформування співробітників компанії через офіційні публікації новин, оголошень та заходів з підтримкою:
- Додавання та видалення категорій-хештегів;
- Вибору декількох категорій на одну новину (із автоматичним додаванням хештегів наприкінці тексту);
- Додавання фото (опціонально: надсилається текст або фото з підписом одним повідомленням);
- Фільтрації аудиторії за посадами (через інлайн-галочки) та містами;
- Попереднього перегляду публікації перед відправкою;
- Безпечної похвильової розсилки (хвилі по 50 осіб з паузами 5-10 хвилин та мікропаузами 0.08с);
- Доступу для **Адміністраторів** та **Наглядачів**;
- Виключення видалених/звільнених співробітників (`status == 'fired'`).

---

## 2. Модель даних (SQLite `database/users.db`)

### 2.1 Таблиця `news_categories`
```sql
CREATE TABLE IF NOT EXISTS news_categories (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT UNIQUE NOT NULL,          -- Назва категорії (наприклад: #новини, #заходи)
    created_at TIMESTAMP,               -- Дата створення у Kyiv time (YYYY-MM-DD HH:MM:SS)
    created_by INTEGER NOT NULL         -- Telegram user_id автора
);
```

## 3. Права доступу та навігація
- **Хто має доступ до розділу «Новини»:**
  - `is_admin` (розробники / головні адміни)
  - `is_observer` (наглядачі з `managers.db` з `process = 'Наглядач'`)
- **Зміна головного меню адмінки (`_admin_cho_keyboard`):**
  - Кнопка `[ 📨 Розсилки ]` тепер відображається не тільки адміністраторам, але й наглядачам (`if is_admin or is_observer`).
- **Меню `[ 📨 Розсилки ]` (`_admin_broadcasts_keyboard`):**
  - Якщо адміністратор:
    - `[ 📋 Ознайомлення ]`
    - `[ 📝 Опитування ]`
    - `[ 📰 Новини ]`
    - `[ 🔙 Назад ]`
  - Якщо наглядач:
    - `[ 📰 Новини ]` (інші розділи розсилок приховані)
    - `[ 🔙 Назад ]`

---

## 4. Структура меню «📰 Новини»
Меню містить дві основні кнопки:
1. **`[ 📢 Опублікувати новину ]`** (`dev_news_create_start`)
2. **`[ 🏷 Керування категоріями ]`** (`dev_news_categories_menu`)
3. **`[ 🔙 Назад ]`** (`dev_broadcasts_menu`)

---

## 5. Керування категоріями (`dev_news_categories_menu`)
1. **Відображення списку:**
   - По кожній категорії виводиться кнопка з видаленням:
     `[ 🏷 #новини ❌ ]` -> `dev_news_cat_del:{id}`
   - Якщо категорій немає: напис «Категорій ще немає. Додайте першу категорію!».
2. **Додавання категорії:**
   - Кнопка `[ ➕ Додати категорію ]` переводить у FSM-стан `NewsCategoryStates.waiting_name`.
   - Бот приймає текст:
     - Очищає від зайвих символів, замінює пробіли на `_`.
     - Гарантує, що починається з `#` (наприклад, введення «новини» автоматично перетворюється на `#новини`).
     - Перевіряє на унікальність.
   - Повідомлення про успіх та повернення до оновленого списку категорій.
3. **Видалення категорії:**
   - По натисканню `❌` видаляє запис з таблиці `news_categories` та оновлює список.

## 6. Майстер публікації новини

### Крок 1: Введення контенту (`NewsCreationStates.waiting_content`)
- Користувач надсилає або:
  - **Текстове повідомлення** (просто текст новини);
  - **Фото з підписом** (зберігається `photo_file_id` та `caption` як текст).
- Якщо тексту немає (надіслано тільки фото без підпису), бот просить додати текст новини.

### Крок 2: Вибір категорій (`NewsCreationStates.selecting_categories`)
- Бот відображає інлайн-клавіатуру з усіма категоріями у вигляді чекбоксів:
  `[ ✅ #новини ]` або `[ ⬜️ #новини ]`
- Можна відзначити одну або декілька категорій (або продовжити без них).
- Кнопка **`[ ➡️ Далі ]`**.
- Кнопка **`[ 🔙 Назад ]`**.

### Крок 3: Вибір аудиторії (`NewsCreationStates.selecting_roles`)
- Вибір ролей із галочками:
  - `[ ✅ Працівник ]`
  - `[ ✅ Стажер ]`
  - `[ ✅ Керівник ]`
  - `[ ✅ Наглядач ]`
- Кнопка `[ ➡️ Далі: Вибір міст ]` -> відкриває вибір міста (`🌐 Всі міста` або назва конкретного міста).
- Фільтрація отримувачів: використовує `get_matching_survey_recipients(roles, city)` з обов'язковим виключенням `fired`/видалених користувачів.

### Крок 4: Попередній перегляд та підтвердження (`NewsCreationStates.confirm_dispatch`)
- Бот надсилає справжній вигляд новини:
  - Фото (якщо було прикріплено).
  - Текст новини.
  - Наприкінці тексту з нового рядка: обрані хештеги (наприклад: `#новини #заходи`).
- Під переглядом виводиться інформаційне повідомлення:
  - Кількість отримувачів: **N** осіб.
  - Цільова аудиторія: обрані посади та місто.
  - Параметри: похвильова відправка по 50 осіб з паузами 5-10 хв.
- Кнопки:
  - **`[ 🚀 Опублікувати ]`**
  - **`[ 🔙 Назад ]`**
  - **`[ ❌ Скасувати ]`**

## 7. Похвильова розсилка (`bot/services/news_broadcaster.py`)
- Функція `start_news_wave_broadcast(bot, recipient_uids, text, photo_file_id=None)`:
  - Розбиває список `recipient_uids` на пачки по 50 осіб.
  - Для кожної хвилі:
    - Відправляє повідомлення (`send_photo` з caption або `send_message`).
    - Мікропауза 0.08с між користувачами.
  - Між хвилями: випадкова пауза `random.randint(300, 600)` секунд.
  - Логує прогрес у системний логер.

---

## 8. Безпека та обробка помилок
- Якщо користувач заблокував бота або видалений з Telegram: помилка логується без переривання розсилки іншим.
- Якщо адміністратор/наглядач скасовує створення — FSM-стан очищується.
- Якщо аудиторія порожня (0 отримувачів) — бот попереджає про це перед запуском.
