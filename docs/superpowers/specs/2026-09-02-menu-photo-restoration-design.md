# Дизайн-специфікація: Відновлення фотошапок у меню та уніфікована навігація

## 1. Мета та контекст
При переході з головних меню (де відображається фотошапка) у текстові підменю (списки, картки, форми без фото) і наступному поверненні назад («⬅️ Назад» або «В головне меню») фотошапка втрачалася або меню залишалося у текстовому вигляді через обмеження Telegram Bot API (неможливість редагувати текст на медіа через `edit_text`) та застарілі шляхи до картинок (`start.png`, `stager.png`, яких більше немає).

Мета: забезпечити надійне відновлення та відображення відповідних фотошапок для всіх головних меню та категорій.

## 3. Архітектура та переходи між станами меню

### 3.1. Уніфікований хелпер відтворення фотошапки `_show_photo_menu`
Знаходиться у [bot/handlers.py](file:///Users/daniildusinskij/All/Dev/Bulka_Edu/bot/handlers.py) та [bot/menus/developer.py](file:///Users/daniildusinskij/All/Dev/Bulka_Edu/bot/menus/developer.py):
1. Перевіряє наявність файлу фото. Якщо відсутній — плавний фолбек на текст.
2. Якщо повідомлення **вже є фотоповідомленням**:
   - Намагається оновити підпис (`edit_caption`).
   - Якщо потрібно замінити саму фотографію (наприклад, перехід між різними категоріями адмінки) — викликає `edit_media(InputMediaPhoto)`.
3. Якщо повідомлення **є текстовим** (або якщо `edit_media` повертає помилку через відсутність медіа):
   - Видаляє старе текстове повідомлення (`await message.delete()`).
   - Відправляє нове фотоповідомлення (`await message.answer_photo(...)`).
4. Безпечно перехоплює помилки Telegram (`TelegramBadRequest: query is too old`, `message not modified`, `message to delete not found`).

### 3.2. Хелпер переходу до текстових підменю `_edit_or_answer`
1. Якщо поточне повідомлення є фотоповідомленням, а цільове підменю — текстове:
   - Видаляє фотоповідомлення (`delete()`) та надсилає текстове (`answer()`).
2. Якщо поточне повідомлення вже текстове:
   - Оновлює через `edit_text()`.
   - У разі помилки (наприклад, повідомлення застаріло або видалено) — надсилає нове `answer()`.
