# Дизайн: Додавання кнопок «Сегеда» та «Радецький» у вибір аудиторії новин

## 1. Мета та контекст
Під час створення новини на кроці 3/4 (вибір аудиторії / ролей) необхідно додати можливість точкового надсилання новин двом ключовим наглядачам:
- **Сегеда Олександр Леонідович** (Telegram ID: `440984923`)
- **Радецький Владислав Леонідович** (Telegram ID: `201151447`)

**Ключова бізнес-вимога:**
При виборі загальної ролі **«Наглядач»** новина **НЕ** повинна надсилатися Сегеді та Радецькому автоматично. Вони мають отримувати новину лише у разі, якщо адміністратор окремо обрав відповідну кнопку («Сегеда» та/або «Радецький»).

---

## 2. Інтерфейс вибору ролей (UI)
У функції `_show_news_roles_selection` меню `bot/menus/developer.py` список кнопок формується у такому порядку:
1. `[✅ / ⬜️] Працівник`
2. `[✅ / ⬜️] Стажер`
3. `[✅ / ⬜️] Керівник`
4. `[✅ / ⬜️] Територіал`
5. `[✅ / ⬜️] Наглядач`
6. `[✅ / ⬜️] Сегеда`
7. `[✅ / ⬜️] Радецький`
8. `[✅ / ⬜️] Адміністратор`
9. `[➡️ Далі (вибір міста)]`
10. `[🔙 Назад]`

Кнопки «Сегеда» та «Радецький» розташовані двома окремими рядками під кнопкою «Наглядач».
За замовчуванням у новій новині увімкнені `['Працівник', 'Стажер']`, а «Сегеда» і «Радецький» — вимкнені.

---

## 3. Логіка формування отримувачів (`database/news.py` / `database/surveys.py`)
Константи:
```python
SPECIAL_NEWS_RECIPIENTS = {
    "Сегеда": 440984923,
    "Радецький": 201151447,
}
EXCLUDED_OBSERVER_IDS = set(SPECIAL_NEWS_RECIPIENTS.values())
```

В алгоритмі `get_matching_news_recipients(roles, target_city)`:
1. **Обробка ролі «Наглядач»:**
   - Якщо «Наглядач» є серед `roles`, витягуються всі наглядачі з бази, але ID із множини `EXCLUDED_OBSERVER_IDS` (`440984923`, `201151447`) фільтруються та **не додаються** до списку отримувачів.
2. **Обробка персональних кнопок «Сегеда» та «Радецький»:**
   - Якщо «Сегеда» є в `roles` -> додається `440984923`.
   - Якщо «Радецький» є в `roles` -> додається `201151447`.
   - Персональні наглядачі не блокуються фільтром по містах (оскільки як наглядачі офісу вони курують мережу).
3. **Фільтр звільнених:**
   - Якщо користувач позначений як `fired` у `managers.db`, він за загальним правилом виключається.

---

## 4. Збереження та сумісність
- Поле `selected_roles` у таблиці `news` зберігає JSON-масив рядків (наприклад: `["Працівник", "Стажер", "Радецький"]`). Жодних міграцій структури таблиці не потрібно.
- У звітах Excel (`bot/services/news_excel.py`) та в картці перегляду новини перелік аудиторії відображатиме `Сегеда` або `Радецький`, якщо вони були обрані.

---

## 5. План тестування
1. **Тест виключення з «Наглядач»:** перевірити, що при `roles = ["Наглядач"]` ID `440984923` та `201151447` відсутні серед отримувачів.
2. **Тест включення «Сегеда» / «Радецький»:** перевірити, що при `roles = ["Сегеда"]` у списку є `440984923`, а при `roles = ["Радецький"]` є `201151447`.
3. **Тест комбінації:** перевірити вибір `["Наглядач", "Радецький"]` — звичайні наглядачі отримують, Радецький отримує, Сегеда — ні.
4. **Тест інтерфейсу бота:** перевірити перемикання кнопок у клавіатурі `_show_news_roles_selection`.
