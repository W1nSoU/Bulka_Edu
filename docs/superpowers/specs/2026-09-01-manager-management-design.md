## 1. Мета та огляд
Реалізація повнофункціонального модуля пошуку та управління керівниками у меню «Команда керівників» для Адміністратора та Територіалів відповідно до Пункту 5 `docs/changes/plan.md` та `docs/changes/MainChange.md`.

## 2. Модель даних та зміни в БД

### 2.1 Таблиця `managers` (у `managers.db`):
* Додаються поля:
  * `status TEXT DEFAULT 'active'` — статус керівника (`'active'` або `'fired'`).
  * `fired_at TIMESTAMP DEFAULT NULL` — дата і час звільнення.
* Автоматична міграція при старті у `database/managers.py` (`init_managers_db`):
  * Перевірка `PRAGMA table_info(managers)` та виконання `ALTER TABLE managers ADD COLUMN ...` за потреби.
  * Усі існуючі керівники отримують `status = 'active'`.

### 2.2 Функції сервісного шару `database/managers.py`:
* `get_all_kerivnyky()`: повертає список керівників з `process = 'Керівник' AND (status = 'active' OR status IS NULL)`.
* `is_manager_user(user_id)`: перевіряє `process = 'Керівник' AND (status = 'active' OR status IS NULL)`. Звільнений керівник миттєво втрачає доступ до функцій керівника.
* `get_manager_by_uid(uid)`: читає інформацію про керівника незалежно від статусу.
* `search_managers(query, city=None, responsible_uid=None)`: пошук за ім'ям, прізвищем, `@username` чи числовим `uid`.
* `fire_manager(uid)`:
  * Встановлює `status = 'fired'`, `fired_at = CURRENT_TIMESTAMP`.
  * Знаходить закріпленого Територіала (або Територіала відповідного міста).
  * Усі активні стажери та працівники (`users.manager_id = uid`) переприв'язуються на `manager_id = territorial_uid` (якщо є) або `NULL` (під управління Адміністратора).
  * Закриває активні сесії `conversations`.
* `update_manager_name(uid, new_name)`: оновлює `full_name` у `managers` та `users`.
* `update_manager_shops(uid, new_shops)`: оновлює `shops` у `managers`. Усі стажери зі старих магазинів переходять до Територіала/Адміна.
* `transfer_users_by_shops(shop_names, target_manager_uid)`: переносить стажерів та працівників обраних магазинів на нового керівника.
* `update_manager_responsible(manager_uid, responsible_uid)`: змінює закріпленого Територіала (`responsible_uid`) або повертає під Адміністратора (`NULL`).

## 3. Інтерфейс користувача та FSM-флоу

### 3.1 Меню «Команда керівників»:
* Відображає список керівників з пагінацією по 10.
* Кнопки:
  * `[ 🔍 Пошук керівника ]` — запуск FSM-пошуку.
  * `[ 👔 ПІБ керівника ]` — клік по керівнику одразу відкриває його картку.
  * `[ ➕ Додати керівника ]` (тільки для Адміна).
  * `[ ⬅️ Назад ]`.

### 3.2 FSM-пошук (`DeveloperStates.waiting_search_manager`):
* Введення: ПІБ, прізвище, username або Telegram ID.
* Результат:
  * 0 знайдено: повідомлення про відсутність результату + кнопки `[ 🔍 Шукати знову ]` та `[ ⬅️ Назад ]`.
  * 1 знайдено: відкривається картка керівника.
  * >1 знайдено: інлайн-список кнопок для вибору конкретного керівника.

### 3.3 Картка керівника:
* Інформація: ПІБ, Username, Telegram ID, Місто, Магазини, Відповідальний (Адміністратор чи Територіал), Кількість стажерів та працівників.
* Кнопки:
  * `[ ✏️ Змінити ]` -> підменю редагування.
  * `[ 🔄 Перепривʼязати ]` -> вибір відповідального Територіала/Адміна.
  * `[ ⬅️ Назад до списку ]`.

### 3.4 Підменю «Змінити»:
* `[ 🏪 Змінити магазин ]`:
  * Скидає поточну прив'язку; стажери старого магазину переходять до Територіала/Адміна.
  * Мульти-вибір магазинів поточного міста (до 5).
  * При підтвердженні — перевіряє наявність людей у нових магазинах та пропонує перевести їх до керівника.
* `[ 👤 Змінити ПІБ ]`:
  * FSM-введення нового імені (мінімум 2 слова).
  * Оновлення в базі та повернення до картки.
* `[ 🚫 Звільнити ]`:
  * Вікно підтвердження з попередженням про втрату доступу та переведення стажерів.
  * Після підтвердження — переведення стажерів на Територіала або Адміна, статус `'fired'`.

## 4. Безпека та права доступу
* Територіал може шукати та управляти тільки керівниками свого міста та закріпленої відповідальності.
* Адміністратор має повний доступ до всіх керівників усіх міст.
* Звільнені керівники втрачають доступ до будь-яких панелей бота.
