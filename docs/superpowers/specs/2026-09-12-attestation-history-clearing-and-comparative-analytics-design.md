**Статус:** Затверджено користувачем

## 1. Мета та контекст

Забезпечити зручне адміністрування хвиль корпоративної атестації та всебічний порівняльний аналіз результатів у динаміці:
1. **Очищення та впорядкування списку в Telegram**: можливість архівувати завершені хвилі (приховуючи їх з основного меню історії без втрати даних), відкривати архів за потреби та безповоротно видаляти тестові/помилкові хвилі.
2. **Збереження та побудова порівняльної аналітики**: генерація багатосторінкового Excel-звіту з фірмовими стилями Bulka та вбудованими графіками `openpyxl.chart`.
3. **Структура звіту (3 обов'язкові аркуші)**:
   - **«Загальне»**: порівняння кожного магазину відносно його власних історичних показників у попередніх хвилях, підсумок по всій мережі та графіки динаміки.
   - **«Керівники»**: динаміка успішності керуючих по кожному магазину з діаграмами.
   - **«Працівники»**: динаміка середнього балу та успішності лінійного персоналу по магазинах з графіками.

## 2. Архітектура та зміни в базі даних (`database/attestation.py`)

### 2.1. Статуси хвиль
Поле `status` в таблиці `attestation_waves` розширюється підтримкою:
- `'draft'` — чернетка.
- `'active'` — активна хвиля.
- `'completed'` — завершена за дедлайном або вручну.
- `'archived'` — заархівована хвиля (прихована з основного списку історії, але доступна для аналітики та перегляду в архіві).

### 2.2. Нові методи в `database/attestation.py`
1. `get_all_waves(include_archived: bool = False, db_path: str = DB_PATH) -> List[Dict[str, Any]]`:
   - За замовчуванням повертає тільки хвилі зі статусами `active` та `completed`.
   - При `include_archived=True` повертає всі хвилі включно з `archived`.
2. `get_archived_waves(db_path: str = DB_PATH) -> List[Dict[str, Any]]`:
   - Повертає список лише хвиль зі статусом `archived`.
3. `archive_completed_waves(db_path: str = DB_PATH) -> int`:
   - Виконує `UPDATE attestation_waves SET status = 'archived' WHERE status = 'completed'`. Повертає кількість заархівованих хвиль.
4. `delete_wave(wave_id: int, db_path: str = DB_PATH) -> bool`:
   - Видаляє хвилю за ID. Завдяки каскадному видаленню `FOREIGN KEY ... ON DELETE CASCADE` видаляються записи в `attestation_wave_shops`, `attestation_participants` та `attestation_attempts`.
5. `get_comparative_attestation_analytics(db_path: str = DB_PATH) -> Dict[str, Any]`:
   - Збирає хронологічний перелік усіх хвиль (крім draft).
   - Агрегує статистику за кожним магазином для кожної хвилі:
     - Загальний результат: к-ть учасників, завершено, середній бал (%), успішно склали (%).
     - Керівники: результат керівника магазину у відповідній хвилі.
     - Працівники: результат працівників магазину у відповідній хвилі.
   - Обчислює загальномережеві показники по кожній хвилі.

## 3. Інтерфейс у Telegram-боті (`bot/menus/attestation.py`)

### 3.1. Оновлення меню «📁 Історія хвиль»
У `dev_att_history_handler`:
- Вгорі меню розміщуються інлайн-кнопки керування:
  - `[ 📊 Порівняльна аналітика (Excel) ]` (`dev_att_export_comparison`)
  - `[ 🗄 Архівувати завершені ]` (`dev_att_archive_completed`)
  - `[ 📦 Архів хвиль (N) ]` (`dev_att_archive_list`) — відображається, якщо є заархівовані хвилі.
- Нижче відображаються кнопки активних та нещодавно завершених хвиль (історія більше не переповнена).

### 3.2. Архів хвиль (`dev_att_archive_list`)
- Відображає перелік заархівованих хвиль із пагінацією та можливістю зайти в картку кожної хвилі або завантажити по ній окремий звіт.
- Кнопка `[ 🔙 Назад до історії ]`.

### 3.3. Видалення тестових/помилкових хвиль
- У картці конкретної хвилі (`dev_att_active_wave_handler`):
  - Кнопка `[ 🗑 Видалити хвилю ]` (`dev_att_del_confirm:{wave_id}`).
  - Екран підтвердження з попередженням:
    * Текст: `⚠️ <b>Видалення хвилі атестації</b>\n\nВи дійсно бажаєте безповоротно видалити хвилю «{title}» та всі пов'язані спроби? Цю дію неможливо скасувати.`
    * Кнопки: `[ ❌ Так, видалити назавжди ]` (`dev_att_del_do:{wave_id}`) та `[ 🔙 Скасувати ]`.

## 4. Генератор порівняльного Excel-звіту (`bot/services/attestation_excel.py`)

Функція `generate_comparative_attestation_xlsx(db_path: str = DB_PATH) -> io.BytesIO`:

### 4.1. Аркуш 1: «Загальне»
- **Заголовок:** `🥐 ПОРІВНЯЛЬНА АНАЛІТИКА КОРПОРАТИВНИХ АТЕСТАЦІЙ BULKA` (золотий фон, жирний шрифт).
- **Підзаголовок:** Дата формування звіту, охоплений період, загальна кількість проведених хвиль.
- **Таблиця динаміки магазинів:**
  - Колонки:
    1. `№`
    2. `Магазин`
    3. `Хвиля 1 (Назва, %)`
    4. `Хвиля 2 (Назва, %)`
    5. `... Хвиля N (%)`
    6. `Середній бал за весь час (%)`
    7. `Динаміка (Δ% остання vs перша)`
    8. `Тренд` (`📈 Зростання` / `📉 Спад` / `➖ Стабільно`)
  - Рядок **«Всього по мережі»** із загальними показниками мережі за кожною хвилею.
- **Вбудовані графіки (`openpyxl.chart`):**
  - **`LineChart`**: «Динаміка середнього балу мережі» (вісь категорій — назви хвиль, дані — рядок мережі).
  - **`BarChart`**: «Рейтинг магазинів за середнім історичним результатом» (вісь категорій — магазини, значення — середній бал %).

### 4.2. Аркуш 2: «Керівники»
- **Заголовок:** `👔 ПОРІВНЯЛЬНИЙ ЗВІТ УСПІШНОСТІ КЕРУЮЧИХ МАГАЗИНІВ`.
- **Таблиця:**
  - Колонки:
    1. `№`
    2. `Магазин`
    3. `Керівник`
    4. Стовпці результатів по хвилях керівників: `Хвиля К1 (%)`, `Хвиля К2 (%)`, ...
    5. `Середній бал (%)`
    6. `Динаміка (Δ%)`
    7. `Рівень кваліфікації` (`⭐️ Високий` / `✅ Достатній` / `⚠️ Потребує уваги`)
- **Графік:**
  - **`BarChart`**: «Порівняльний рейтинг керуючих магазинів».

### 4.3. Аркуш 3: «Працівники»
- **Заголовок:** `👥 ПОРІВНЯЛЬНИЙ ЗВІТ УСПІШНОСТІ ЛІНІЙНОГО ПЕРСОНАЛУ`.
- **Таблиця:**
  - Колонки:
    1. `№`
    2. `Магазин`
    3. `Середня к-ть працівників на хвилю`
    4. Стовпці середнього балу працівників по хвилях: `Хвиля П1 (%)`, `Хвиля П2 (%)`, ...
    5. `Середній бал персоналу (%)`
    6. `Частка успішного складання (%)`
    7. `Динаміка команди (Δ%)`
- **Графік:**
  - **`LineChart`**: «Зміна кваліфікації персоналу по ключових магазинах».
