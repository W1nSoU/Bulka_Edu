# Дизайн: Керування посадами, переведення ролей та безпечне видалення стажерів (Завдання 63–66)

**Дата:** 2026-09-10  
**Статус:** Схвалено користувачем  
**Цільові завдання:**  
- `63`: Чи не буде зникати навчання якщо назва посади зміниться.  
- `64`: Можливість видаляти посади через інтерфейс (з перевіркою відсутності закріплених користувачів).  
- `65`: Зміна посади користувачу з коректною адаптацією навчання:  
  - Для **Працівника** (`status == 'Працівник'`): зберігається статус працівника, всі дні нової посади стають повністю відкритими для вільного перегляду.  
  - Для **Стажера** (`status != 'Працівник'`): старий прогрес очищується, навчання розпочинається наново з 1-го дня нової посади, наступні дні відкриваються поступово.  
- `66`: Безпечне видалення користувача/стажера без залишку "фантомних" записів прогресу чи помилок, щоб повторне додавання на нову або ту саму посаду не ламало логіку днів.

## 1. Поточний стан та аналіз

1. **Завдання 63 (Перейменування посади):**
   - У `database/positions.py` функція `rename_position(old_name, new_name)` оновлює `materials`, `users`, `test_errors`, `training_events`.
   - Проте таблиця `tokens` (інвайти, що очікують реєстрації) не оновлюється. Якщо створено токен з роллю `old_name`, після перейменування стажер зареєструється зі старою роллю.
   - **Рішення:** Додати `UPDATE tokens SET role = ? WHERE role = ?` у `rename_position`.

2. **Завдання 64 (Видалення посади в UI):**
   - У `database/positions.py` вже є `delete_position(position_id)`, яка перевіряє `SELECT COUNT(*) FROM users WHERE role = ?`. Якщо користувачі є — повертає `(False, "...")`.
   - В UI меню розробника/адміністратора (`bot/menus/developer.py` -> `dev_pos_view`) відсутня кнопка видалення посади та обробники підтвердження видалення.
   - Також при видаленні посади необхідно видаляти залишкові матеріали (`DELETE FROM materials WHERE role = ?`) та невикористані токени цієї ролі.

3. **Завдання 65 (Зміна посади працівнику/стажеру):**
   - Зараз `developer_process_change_role` лише виконує `UPDATE users SET role = ? WHERE user_id = ?` без скидання прогресу в БД чи пам'яті (`user_progress`).
   - Якщо працівник був пекарем (5 днів) і став касиром (4 дні), його старий прогрес веде до багів.
   - **Нова логіка:**
     - Якщо `status == 'Працівник'`:
       - `role = new_role`, `status = 'Працівник'`.
       - Очистити `progress` для цього користувача.
       - Визначити кількість днів для `new_role` (`get_days_count_for_role`).
       - Для кожного дня `1..N` створити запис у `progress`: `manual_open = 1, completed = 1`.
       - Очистити кеш `user_progress.pop(user_id, None)`.
     - Якщо `status != 'Працівник'` (Стажер):
       - `role = new_role`.
       - Очистити `progress` для цього користувача.
       - Відкрити День 1: `manual_open = 1, completed = 0`.
       - Очистити кеш `user_progress.pop(user_id, None)`.

4. **Завдання 66 (Чисте видалення стажера / користувача):**
   - При видаленні користувача через `delete_user(user_id)` або меню адміністратора/керівника:
     - Видалити записи з `users`.
     - Видалити записи з `progress`.
     - Видалити записи з `test_errors`.
     - Очистити пам'ять `user_progress.pop(user_id, None)`.
     - Видалити або інвалідувати активні токени, пов'язані з цим `user_id`.

## 2. Архітектура та зміни компонентів

### А. База даних (`database/positions.py` та `database/users.py`)

1. **`database/positions.py`**:
   - `rename_position(old_name, new_name)`:
     ```python
     await db.execute("UPDATE tokens SET role = ? WHERE role = ?", (new_name, old_name))
     ```
   - `delete_position(position_id)`:
     - Перевірка наявності користувачів з роллю.
     - Якщо користувачів 0:
       - Очистити `materials` для цієї ролі: `DELETE FROM materials WHERE role = ?`.
       - Очистити `tokens` для цієї ролі: `DELETE FROM tokens WHERE role = ?`.
       - Видалити посаду: `DELETE FROM positions WHERE id = ?`.
       - Повернути `(True, "Посаду успішно видалено")`.

2. **`database/users.py`**:
   - Нова/оновлена функція `change_user_role(user_id: int, new_role: str) -> bool`:
     - Отримати поточний `status` користувача.
     - `UPDATE users SET role = ? WHERE user_id = ?`.
     - `DELETE FROM progress WHERE user_id = ?`.
     - Якщо `status == 'Працівник'`:
       - Отримати `days = await get_days_count_for_role(new_role)`.
       - Для `d in 1..days`: `INSERT INTO progress (user_id, day, completed, manual_open) VALUES (?, ?, 1, 1)`.
     - Якщо `status != 'Працівник'`:
       - Відкрити День 1: `INSERT INTO progress (user_id, day, completed, manual_open) VALUES (?, 1, 0, 1)`.
     - Очистити `user_progress.pop(user_id, None)`.
     - Повернути `True`.
   - `delete_user(user_id: int) -> bool`:
     - `DELETE FROM users WHERE user_id = ?`.
     - `DELETE FROM progress WHERE user_id = ?`.
     - `DELETE FROM test_errors WHERE user_id = ?`.
     - `DELETE FROM tokens WHERE user_id = ?`.
     - `user_progress.pop(user_id, None)`.

### Б. Інтерфейс бота (`bot/menus/developer.py` та клавіатури)

1. **Керування посадами (`dev_pos_view`)**:
   - Додати кнопку: `🗑 Видалити посаду` (`callback_data=f"dev_pos_del_ask:{pos_id}"`).
   - Хендлер `dev_pos_del_ask:{pos_id}`:
     - Отримує назву посади.
     - Перевіряє кількість користувачів: `COUNT(*) FROM users WHERE role = ?`.
     - Якщо користувачі є: показує повідомлення:
       > ⚠️ **Неможливо видалити посаду "{name}"**  
       > За цією посадою наразі закріплено {count} користувачів.  
       > Спочатку переведіть або видаліть користувачів.  
       > [🔙 До посади]
     - Якщо користувачів 0: показує екран підтвердження:
       > ❓ **Ви дійсно хочете видалити посаду "{name}"?**  
       > ⚠️ Усі навчальні матеріали для цієї посади також буде видалено!  
       > [🗑 Так, видалити] (`dev_pos_del_confirm:{pos_id}`)  
       > [❌ Скасувати] (`dev_pos_view:{pos_id}`)
   - Хендлер `dev_pos_del_confirm:{pos_id}`:
     - Викликає `delete_position(pos_id)`.
     - Виводить сповіщення та повертає до списку посад `dev_positions`.

2. **Зміна ролі користувача (`developer_process_change_role`)**:
   - Викликає `change_user_role(target_user_id, new_role)`.
   - Формує інформативне повідомлення:
     - Якщо користувач був "Працівник": *"✅ Посаду змінено на {new_role}. Оскільки користувач має статус Працівника, всі дні нової посади автоматично відкрито для вільного доступу."*
     - Якщо користувач "Стажер": *"✅ Посаду змінено на {new_role}. Навчання розпочато заново з 1-го дня нової посади."*
   - Якщо бот має чат з користувачем — відправляє сповіщення про зміну посади та оновлення навчальної програми.
