# Специфікація: Глобальна видимість стажерів для Адміністратора та майстер прив'язки стажера до Керівника / Територіала

**Дата:** 2026-09-10  
**Статус:** Узгоджено  
**Тема:** Адміністрування стажерів, генерація інвайт-посилань з вибором відповідального в місті, глобальна видимість персоналу мережі.

---

## 1. Мета та огляд проблеми
1. **Проблема при генерації посилання стажера адміністратором:**
   Раніше при додаванні стажера адміністратором бот підставляв ID самого адміністратора або автоматично намагався знайти керівника точки. Адміністратор не мав можливості вручну обрати, до кого саме в обраному місті прив'язати новенького — до безпосереднього керівника конкретного магазину, до іншого досвідченого керівника цього ж міста, чи до міського Територіала.
2. **Вимога до прив'язки керівника:**
   Керівники магазинів та Територіали мають чітку прив'язку до міста (колонка `city` в базі `managers`). Крім того, керівник може керувати одразу кількома магазинами (список `shops`). Програма повинна пропонувати лише тих відповідальних осіб, які належать до обраного міста.
3. **Глобальна видимість стажерів:**
   Адміністратор мережі повинен мати 100% видимість усіх стажерів по всій мережі у всіх меню перегляду персоналу, тоді як Територіал повинен бачити виключно людей свого міста та свого напрямку (ТЗ/ВВ).

---

## 2. Послідовність майстра створення запрошення (User Flow)
Послідовність кроків в `bot/menus/developer.py` (`dev_users_add`):
```
1. Вибір міста (Хмельницький, Вінниця, тощо)
       ⬇️
2. Вибір магазину (або пропуск, якщо місто без магазинів)
       ⬇️
3. Вибір відповідального (Керівник магазину / Територіал / Інші керівники міста / Автоматично)
       ⬇️
4. Вибір посади (Продавець-консультант, Пекар, тощо)
       ⬇️
5. Генерація 24-годинного посилання-запрошення
```

### 2.1. Екран вибору відповідального (Крок 3)
Після вибору магазину надсилається екран:
```text
🏙️ Місто: <b>{city}</b>
🏪 Магазин: <b>{shop}</b>

👤 <b>До кого закріпити стажера?</b>
Оберіть керівника магазину або територіала:
```

**Кнопки формуються на основі активних записів у `managers` де `city == chosen_city`:**
1. **Керівник(и) обраного магазину:**
   - Знаходиться керівник, у чиєму списку магазинів (`shops`) присутній обраний магазин.
   - Текст кнопки: `👔 [Прізвище І. О.] (Керівник {скорочені магазини})`
   - Приклад: `👔 Зубенко М. П. (Керівник B-19, B-22)`
2. **Територіал(и) міста:**
   - Знаходяться всі діючі територіали міста.
   - Текст кнопки: `🗺 [Прізвище І.] (Територіал {тип: ТЗ або ВВ})`
   - Приклад: `🗺 Ірина Д. (Територіал ТЗ)`
3. **Кнопка розгортання «👔 Інші керівники міста»:**
   - При натисканні відображає перелік інших керівників магазинів цього ж міста (для випадків, коли треба призначити наставником керівника сусідньої точки).
4. **Кнопка «⚡️ Автоматично за магазином»:**
   - Закріплює за стандартним системним правилом (за керівником магазину, якщо він є, інакше — за територіалом).
5. **Кнопка «⬅️ Назад»:**
   - Повертає до вибору магазину.

## 3. Збереження даних та реєстрація стажера (Data Flow)

1. **Токен запрошення (`database/tokens.py`):**
   - При виборі конкретного керівника чи територіала його `uid` фіксується як цільовий наставник (`target_manager_id`).
   - У токені зберігається `manager_id = target_manager_id` (або `target_manager_id` в `extra_data`, а `creator_id` фіксує ID адміністратора).
   - Якщо обрано «⚡️ Автоматично», `target_manager_id = None`.

2. **Обробка при реєстрації (`bot/handlers.py`):**
   - Коли користувач стартує за посиланням:
     ```python
     if target_manager_id:
         assigned_manager_id = target_manager_id
     else:
         # стандартний автоматичний fallback:
         assigned_manager_id = await get_manager_by_shop(city, shop)
         if not assigned_manager_id:
             assigned_manager_id = await get_appropriate_territorial_for_user(city, role)
     ```
   - Запис у таблицю `users`: `manager_id = assigned_manager_id`, `city = city`, `shop = shop`, `role = role`.

3. **Сповіщення:**
   - Призначений керівник / територіал отримує повідомлення:
     > 👤 **Новий співробітник зареєструвався!**
     > ПІБ: {full_name} | Посада: {role} | Місто: {city} | Магазин: {shop}
   - Якщо посилання створював Адміністратор (і він не є призначеним керівником), Адміністратор також отримує підтвердження:
     > ✅ **Стажер зареєструвався за вашим посиланням!**
     > Закріплено за: {manager_name} ({manager_role})

## 4. Глобальна видимість стажерів для Адміністратора

1. **Списки стажерів у `bot/menus/developer.py`:**
   - У функціях `developer_list_interns`, `developer_list_workers`, `developer_list_interns_no_manager`, `developer_list_all_users`:
     ```python
     has_access, is_admin, is_territorial = await _check_access(callback)
     if is_territorial and not is_admin:
         users = await _filter_users_for_territorial(callback.from_user.id, users)
     ```
   - Адміністратор (`is_admin == True`) **ніколи** не обмежується фільтром міста чи типу територіала.
2. **Відображення інформації в картках списку:**
   - У списку стажерів відображається повна локація:
     `{idx}. {full_name} (ID: {user_id})`  
     `@{username} | {role} | {city} · {shop_short} | {current_block} день`
3. **Експорт в Excel (`dev_interns_export_xlsx`):**
   - Для адміністратора формується таблиця по всій мережі з вказанням міста, магазину, закріпленого керівника та прогресу.

---

## 5. Тестування та валідація
1. Перевірка майстра створення стажера адміністратором:
   - Вибір міста «Хмельницький» ➔ вибір магазину «B-19 ...» ➔ перевірка наявності кнопок керівника точки, територіала, «Інші керівники», «Автоматично».
   - Вибір іншого міста без керівників магазинів ➔ відображення територіала міста та кнопки «Автоматично».
2. Перевірка генерації посилання з обраним керівником:
   - Проходження реєстрації тестовим акаунтом ➔ перевірка поля `manager_id` у таблиці `users`.
3. Перевірка списків користувачів:
   - Вхід під Адміністратором ➔ відображення всіх стажерів усіх міст.
   - Вхід під Територіалом ➔ фільтрація виключно за містом та напрямком Територіала.
