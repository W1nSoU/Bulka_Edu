# Дизайн-специфікація: Підсистема «Розіграші» (Giveaways) у BulkaEdu

**Дата:** 2026-11-16  
**Статус:** Затверджено  
**Автор:** Команда розробки BulkaEdu

---

## 1. Мета та бізнес-контекст

Додати до корпоративного навчального бота BulkaEdu повноцінний модуль проведення розіграшів та активностей для працівників мережі. Адміністратори отримують зручний покроковий конструктор у вкладці «Розсилки», автоматизований прийом відповідей та медіафайлів від обраних ролей, а також вивантаження результатів у форматі `.xlsx` або багатотомних `.zip`-архівів.

---

## 2. Ключові обмеження та архітектурні рішення

1. **Один активний розіграш одночасно**: у системі в будь-який момент може бути активним лише один розіграш (`status = 'active'`). Поки він триває або не досяг дедлайну, створення нового розіграшу заблоковане.
2. **Обов'язковий анонс за вибором адміністратора**: при запуску розіграшу адміністратор може увімкнути або вимкнути хвильову розсилку анонсу в особисті повідомлення. Незалежно від цього, кнопка **`🎁 Розіграш`** з'являється у головному меню всіх співробітників обраної аудиторії.
3. **Одноразова участь з перевіркою формату**: користувач може взяти участь у розіграші рівно **один раз** (`UNIQUE(raffle_id, user_id)`). Перед фіксацією відповіді система перевіряє її формат (якщо формат заданий) та показує екран попереднього перегляду з кнопками `[✅ Підтвердити участь]` та `[✏️ Змінити]`. Некоректний ввід не спалює спробу, а видає підказку.
4. **Термін зберігання та очищення (60 днів)**: розіграші відображаються в «Історії розіграшів» протягом 60 днів після завершення. Після спливу 60 днів фонова задача автоматично видаляє завантажені фото, відео та файли з диска (`data/raffles_media/{raffle_id}/`), а сам розіграш зникає зі списку активної історії. Адміністратор також може видалити розіграш вручну.
5. **Експорт результатів без вбудованого рандомайзера**: визначення переможців відбувається поза ботом. Система вивантажує повний список учасників та медіафайли:
   - для текстових і кнопкових форматів - `.xlsx` файл у стилі звітів новин;
   - для фото, відео або файлів - `.xlsx` таблиця + `.zip` архів (або серія `.zip` архівів по <= 45 МБ кожен), де кожен файл перейменований за ПІБ учасника.

## 3. Модель даних (`database/raffles.py`)

### Таблиця `raffles`

| Колонка | Тип | Опис |
| :--- | :--- | :--- |
| `id` | INTEGER PRIMARY KEY AUTOINCREMENT | Унікальний ідентифікатор розіграшу |
| `title` | TEXT NOT NULL | Коротка назва розіграшу (для списків та заголовків) |
| `text` | TEXT NOT NULL | Повний текст умов (підтримка HTML як у новинах) |
| `media_type` | TEXT | Тип обкладинки умов: `'photo'`, `'video'` або `NULL` |
| `photo_file_id` | TEXT | Telegram `file_id` фотографії умов |
| `video_file_id` | TEXT | Telegram `file_id` відео умов |
| `participation_type` | TEXT NOT NULL | `'button'`, `'text'`, `'formatted_text'`, `'media'`, `'document'` |
| `text_format` | TEXT | Підформат для `formatted_text`: `'any'`, `'numeric'`, `'score'` або `NULL` |
| `selected_roles` | TEXT NOT NULL | JSON-масив обраних ролей (напр. `["Працівник", "Стажер"]`) |
| `selected_city` | TEXT DEFAULT 'all'` | Місто або `'all'` для всієї мережі |
| `deadline` | TIMESTAMP NOT NULL | Дата і час завершення (`YYYY-MM-DD HH:MM:SS` Europe/Kyiv) |
| `send_announcement` | INTEGER DEFAULT 0 | `1` - розсилати анонс в особисті, `0` - лише кнопка в меню |
| `status` | TEXT NOT NULL DEFAULT 'active'` | `'active'` або `'completed'` |
| `media_cleaned` | INTEGER DEFAULT 0 | `1`, якщо медіафайли з диска вже видалені після 60 днів |
| `created_at` | TIMESTAMP NOT NULL | Час створення |
| `completed_at` | TIMESTAMP | Фактичний час завершення (достроково або за дедлайном) |
| `created_by` | INTEGER NOT NULL | Telegram `user_id` адміністратора |

### Таблиця `raffle_submissions`

| Колонка | Тип | Опис |
| :--- | :--- | :--- |
| `id` | INTEGER PRIMARY KEY AUTOINCREMENT | Унікальний ID заявки |
| `raffle_id` | INTEGER NOT NULL | Посилання на `raffles(id)` (`ON DELETE CASCADE`) |
| `user_id` | INTEGER NOT NULL | Telegram `user_id` учасника |
| `user_name` | TEXT | Telegram `@username` |
| `user_full_name` | TEXT | ПІБ з таблиці `users` або `managers` |
| `shop_name` | TEXT | Магазин / підрозділ учасника |
| `user_city` | TEXT | Місто учасника |
| `user_role` | TEXT | Посада / роль учасника |
| `submission_text` | TEXT | Текст відповіді, число, рахунок або підпис файлу |
| `media_type` | TEXT | `'photo'`, `'video'`, `'document'` або `NULL` |
| `file_id` | TEXT | Telegram `file_id` надісланого медіа або документа |
| `local_file_path` | TEXT | Відносний/абсолютний шлях до файлу в `data/raffles_media/{raffle_id}/` |
| `file_size` | INTEGER DEFAULT 0 | Розмір файлу в байтах |
| `created_at` | TIMESTAMP NOT NULL | Час підтвердження участі |

**Обмеження унікальності:** `UNIQUE(raffle_id, user_id)`.

## 4. Формати участі та валідація

1. **`button` - Натискання «Взяти участь»**:
   - Користувач бачить умови розіграшу та кнопку `[🎁 Взяти участь]`.
   - Після натискання заявка одразу фіксується зі статусом `«Взяв участь (кнопка)»`.
2. **`text` - Відправка повідомлення**:
   - Приймається будь-який непорожній текст (`submission_text`).
3. **`formatted_text` - Відправка повідомлення з форматом**:
   - **`any` (Текстовий)**: будь-який непорожній текст.
   - **`numeric` (Числовий)**: приймаються лише цілі або дробові числа (`^[+-]?\d+(?:[.,]\d+)?$`). Користувачеві надається приклад у разі помилки (напр., `42` або `12.5`).
   - **`score` (Рахунок)**: приймається формат матчу `X:Y` (`^(\d+)\s*:\s*(\d+)$`), наприклад `0:0`, `2:1`. Пробіли навколо двокрапки нормалізуються до `X:Y`.
4. **`media` - Надсилання фото або відео**:
   - Приймається фото (`message.photo`) або відео (`message.video`), за потреби разом із текстовим підписом (`message.caption`).
5. **`document` - Надсилання файлів**:
   - Приймається документ (`message.document`), а також за потреби текстовий підпис (`message.caption`).

## 5. Адміністративний інтерфейс (`bot/menus/raffles.py`)

У клавіатурі `_admin_broadcasts_keyboard` (`bot/menus/developer.py`) додається кнопка **`🎁 Розіграші`** (`callback_data="dev_raffles_menu"`).

### Меню «🎁 Розіграші»
- Якщо є активний розіграш: відображається його назва, формат, дедлайн та кількість учасників; кнопка переходу до картки `[🔥 Керувати активним розіграшем]` і швидка кнопка `[📥 Вивантажити учасників]`.
- Якщо активного розіграшу немає:
  - кнопка `[➕ Створити розіграш]`;
  - якщо існує останній завершений розіграш (в межах 60 днів) - швидка кнопка `[📥 Вивантажити учасників (останній)]`.
- Кнопка `[📜 Історія розіграшів]` - список розіграшів за останні 60 днів з пагінацією по 6 елементів.

### Майстер створення розіграшу (FSM `RaffleCreateStates`)
1. **Контент та умови (`waiting_content`)**: адмін надсилає текст або фото/відео з текстом (так само, як у створенні новин). Назва розіграшу автоматично формується з першого рядка очищеного тексту (до 60 символів).
2. **Вибір типу участі (`selecting_type` / `selecting_text_format`)**: 5 варіантів; при виборі «Повідомлення з форматом» уточнюється формат (`Текстовий`, `Числовий`, `Рахунок`).
3. **Дата завершення (`selecting_deadline`)**: швидкі кнопки `[⏳ 1 день]`, `[⏳ 3 дні]`, `[⏳ 1 тиждень]`, `[⏳ 2 тижні]` або ручне введення у форматі `ДД.ММ.РРРР ГГ:ХХ` (або `ДД.ММ.РРРР`, що встановлює час `23:59`).
4. **Аудиторія (`selecting_roles` -> `selecting_city`)**: мульти-вибір ролей (`Працівник`, `Стажер`, `Керівник`, `Територіал`, `Наглядач`, `Адміністратор`) з кнопкою «Обрати всі» та вибір міста (`Усі міста` або конкретне місто).
5. **Підтвердження та запуск (`confirm_launch`)**: перегляд усіх параметрів, перемикач `[🔔 Анонс в особисті: Увімкнено / Вимкнено]` та кнопка `[🚀 Запустити розіграш]`.

### Картка розіграшу
- Повна статистика, умови та кнопки:
  - `[📥 Вивантажити учасників]`
  - `[🛑 Завершити достроково]` (тільки для активного)
  - `[🗑 Видалити розіграш]` (з екраном підтвердження)

## 6. Користувацький інтерфейс та інтеграція в головне меню

1. У функції побудови головного меню (`bot/keyboards.py` -> `main_menu_keyboard`) додається параметр `has_active_raffle: bool = False`.
2. При показі головного меню (`show_student_main_menu`, `show_manager_main_menu`, `show_developer_main_menu`, `show_observer_main_menu` у `bot/handlers.py`) викликається `is_user_eligible_for_active_raffle(uid)`. Якщо користувач підпадає під обрані ролі та місто і дедлайн ще не минув, у головному меню з'являється кнопка **`🎁 Розіграш`**.
3. Якщо дедлайн минув або розіграш зупинено достроково, при наступному відкритті головного меню кнопка автоматично зникає.
4. Перехід за кнопкою **`🎁 Розіграш`**:
   - Якщо користувач ще не брав участі: виводяться умови (з фото/відео за наявності) та очікується одна дія (кнопка або повідомлення/файл) + кнопка `[🔙 Назад]`.
   - Після валідації повідомлення показується прев'ю введених даних із кнопками `[✅ Підтвердити участь]`, `[✏️ Змінити]`, `[🔙 Назад]`.
   - Якщо користувач вже взяв участь: під умовами виводиться **`✅ Ви берете участь в акції!`** та кнопка `[🔙 Назад]`, що повертає в головне меню і очищує FSM.

## 7. Експорт учасників (`bot/services/raffle_exporter.py`)

1. **Excel-звіт (`generate_raffle_report_xlsx`)**:
   - Генерується для всіх типів розіграшів.
   - Аркуш 1 «Загальний»: метадані розіграшу, формат, аудиторія, статус, умови, загальна кількість учасників.
   - Аркуш 2 «Учасники»: `№`, `ПІБ`, `Магазин`, `Посада`, `Місто`, `Username`, `Відповідь / Файл`, `Час участі`.
   - Візуальне оформлення відповідає стандартам `news_excel.py`.
2. **ZIP-архівація медіа та файлів (`generate_raffle_media_zips`)**:
   - Виконується для розіграшів із типом `media` або `document`.
   - Назва кожного файлу в архіві змінюється на ПІБ учасника з оригінальним розширенням (наприклад, `Іваненко_Петро_Олегович.jpg`). При повторенні однакового ПІБ автоматично додається суфікс з індексом або `user_id`.
   - Якщо сумарний розмір файлів перевищує 45 МБ (безпечний запас до ліміту Telegram у 50 МБ), файли пакуються у кілька незалежних `.zip` архівів (`Розіграш_{id}_частина_1.zip`, `Розіграш_{id}_частина_2.zip`, ...), які по черзі надсилаються адміністратору разом із супутнім `.xlsx` файлом.

## 8. Планувальник та обслуговування (`main.py`)

У планувальнику `AsyncIOScheduler` реєструється регулярна задача `raffle_maintenance_loop` (кожні 10 хвилин):
1. Переводить протерміновані активні розіграші (`deadline <= now`) у статус `'completed'`.
2. Викликає `cleanup_expired_raffle_media(days=60)`: знаходить завершені розіграші, де минуло понад 60 днів, видаляє директорію `data/raffles_media/{raffle_id}` та обнуляє `local_file_path` у БД.

## 9. План тестування

Модульні та інтеграційні тести у `tests/test_raffles.py`:
- Життєвий цикл розіграшу та блокування другого активного розіграшу.
- Таргетинг аудиторії за ролями і містами та зникнення кнопки після дедлайну.
- Валідатор форматів (`any`, `numeric`, `score`), одноразова участь (`UNIQUE(raffle_id, user_id)`).
- Генерація `.xlsx` звіту і розбиття великих наборів файлів на частини `.zip` до заданого ліміту розміру з перейменуванням на ПІБ.
- Фільтрація історії за 60 днів та автоматичне очищення медіа з диска.
