# Дизайн-документ: Роль «Наглядач» (Observer Role)

## 1. Огляд та Мета
Роль «Наглядач» є копією ролі Адміністратора з повним доступом до перегляду системи, але з жорсткими обмеженнями (Read-Only). Наглядач може бачити всі навчальні матеріали та аналітику, але не має права нічого редагувати, видаляти, змінювати або експортувати у вигляді файлів звітів.

---

## 2. Обмеження та Права Доступу Наглядача

| Категорія | Дозволено для Наглядача | Заборонено для Наглядача |
| :--- | :--- | :--- |
| **Навчальні матеріали** | Повний перегляд усіх матеріалів (сторінки, тести, відео, фото, змісти, нагадування тем) | Кнопки «Виправити», «Вставити між сторінками», «Змінити сторінки», редагування тестів/відео |
| **Аналітика** | Перегляд усіх екранів аналітики (прогрес стажерів, статистика, відмови, активність тощо) | Генерація та завантаження **XLSX-звітів** (`dev_analytics_xlsx`) |
| **Команда Bulka** | Перегляд списків працівників, стажерів, керівників та їх карток | Звільнення, зміна ПІБ, зміна магазинів/міст, додавання нових працівників |
| **Адміністративні функції** | — | Токени, Health-статус, зміна/додавання посад та міст, управління командою адміністраторів/територіалів/наглядачів |

---

## 3. Модель Даних та Сервіси (`database/managers.py` та `database/tokens.py`)

### 3.1. Зберігання в базі (`managers.db`)
* Роль фіксується у стовпчику `process = 'Наглядач'`.
* Поле `responsible_uid` містить `Telegram ID` Адміністратора, який згенерував посилання.
* Поле `status = 'active'`.

### 3.2. Функції в `database/managers.py`
* `is_observer_user(user_id: int) -> bool`: Перевірка активного статусу наглядача.
* `get_all_observers() -> list[dict]`: Отримання списку всіх активних наглядачів.
* `get_observer_by_uid(uid: int) -> dict | None`: Отримання інформації про наглядача.
* `delete_observer_by_uid(uid: int)`: Встановлення статусу `status = 'fired'` (або видалення запису).

### 3.3. Генерація токенів (`database/tokens.py`)
* `generate_token(manager_id=admin_uid, role='Наглядач', expires_in_hours=24)`:
  * Генерує одноразовий токен на 24 години для реєстрації наглядача.

---

## 4. Інтерфейс та Флоу Реєстрації

### 4.1. Флоу реєстрації за посиланням (`bot/handlers.py`)
1. Користувач переходить за посиланням `https://t.me/<bot>?start={admin_uid}-{token}`.
2. Бот валідує токен: якщо `role == 'Наглядач'`, переводить користувача у стан введення ПІБ `RegistrationStates.waiting_for_full_name`.
3. Після введення ПІБ:
   * Користувач зберігається в `users` та додається в `managers.db` (`process = 'Наглядач'`, `full_name = full_name`, `responsible_uid = admin_uid`, `status = 'active'`).
   * Токен позначається як використаний (`use_token`).
   * Відправляється вітальне повідомлення та відкривається меню Наглядача.

### 4.2. Головне меню Наглядача (`bot/keyboards.py`)
* При `/start`:
  * Кнопка: `[ 👁 Панель Наглядача ]`
  * Кнопка: `[ 👤 Профіль ]`

### 4.3. Панель Наглядача (`bot/menus/developer.py`)
* Адаптоване меню адмін-панелі:
  * `[ 📚 Навчальні матеріали ]` — доступ лише для перегляду (без кнопок редагування).
  * `[ 📊 Аналітика ]` — доступ до аналітики (кнопка XLSX звіт відсутня/заблокована).
  * `[ 👥 Команда Bulka ]` — перегляд карток та списків (кнопки дій відсутні).

---

## 5. Управління Наглядачами в Панелі Адміністратора

1. **Розділ «Команда Bulka» -> «Наглядачі» (`dev_observers_menu`):**
   * Список наглядачів у вигляді інлайн-кнопок `[ 👁 ПІБ ]` (пагінація по 6).
   * Кнопка `[ ➕ Створити запрошення ]` (`dev_observer_create_invite`).
   * Кнопка `[ ⬅️ Назад ]`.
2. **Створення запрошення:**
   * Бот генерує токен та видає готове клікабельне посилання з терміном дії 24 години.
3. **Картка Наглядача (`dev_observer_card`):**
   * ПІБ, Telegram ID, Username, хто призначив, дата.
   * Кнопка `[ 🗑 Видалити наглядача ]` з підтвердженням.
   * Кнопка `[ ⬅️ Назад ]`.

---

## 6. План Перевірки (Verification Plan)
1. **Тестування генерації токена:** Створення токена для ролі «Наглядач» та перевірка валідності.
2. **Тестування реєстрації:** Перехід за посиланням, введення ПІБ, створення запису в `managers.db` з `process = 'Наглядач'`.
3. **Тестування обмежень меню:** Перевірка, що під роллю Наглядача недоступні кнопки виправлення матеріалів, кнопки зміни користувачів та кнопка завантаження XLSX.
4. **Тестування управління Наглядачами:** Перевірка списку наглядачів, перегляду картки та видалення через панель Адміністратора.
