# Дизайн-специфікація: Багаторазове (офісне) та персональне запрошення Наглядачів

**Дата:** 2026-11-06  
**Статус:** Затверджено

## 1. Мета
Забезпечити можливість швидкого додавання всього офісу на роль «Наглядач» за одним спільним посиланням-запрошенням (діє 24 години без обмеження кількості переходів із можливістю ручної деактивації), зберігаючи при цьому можливість створювати персональні одноразові посилання для додавання окремих наглядачів у майбутньому.

## 2. Архітектура та компоненти

### 2.1. Підсистема токенів (`database/tokens.py`)
- Підтримка прапорця `multi_use: true` у JSON-полі `extra_data` таблиці `tokens`.
- **`get_token_data(token)`**:
  - Спочатку розбирає `extra_data`.
  - Якщо `extra.get("revoked")` є істинним — повертає `{"status": "expired"}`.
  - Якщо `extra.get("multi_use")` є істинним — пропускає перевірку `used_by is not None` і перевіряє лише термін дії `expires_at`.
  - Для одноразових токенів поведінка залишається незмінною (`used_by is not None` -> `already_used`).
- **`use_token(token, user_id)`**:
  - Для багаторазового токена (`multi_use: true`): додає `user_id` у масив `extra["used_by_list"]` (без дублікатів), оновлює `extra_data` та `used_at`, залишаючи `used_by = NULL` (щоб посилання залишалося активним для інших співробітників офісу до закінчення терміну дії).
  - Для одноразового токена: як і раніше, встановлює `used_by = user_id` та `used_at = now`.
- **Нові функції**:
  - `get_active_multi_use_token(role: str = "Наглядач") -> dict | None` — повертає активний багаторазовий токен для вказаної ролі (де `expires_at > now`, не `revoked`), включаючи кількість уже зареєстрованих за ним користувачів (`used_count`) та `expires_at`.
  - `revoke_token(token: str) -> bool` — деактивує багаторазовий токен (встановлює `extra["revoked"] = True` та `expires_at = now`).

### 2.2. Інтерфейс Адміністратора (`bot/menus/developer.py`)
- У меню `👁 Наглядачі` (`_build_observers_menu_view`) замість однієї кнопки створення запрошення відображаються дві кнопки (для не-наглядачів):
  - `➕ Додати одного (одноразове)` (`dev_obs_create_invite`)
  - `🏢 Спільне посилання для офісу (24 год)` (`dev_obs_office_invite`)
- Обробник `developer_observer_office_invite` (`dev_obs_office_invite` / `dev_obs_regen_office_invite`):
  - Якщо викликано `dev_obs_regen_office_invite`, деактивує попередній активний груповий токен (якщо був) і створює новий на 24 години з `extra_data={"multi_use": True, "used_by_list": []}`.
  - Якщо викликано `dev_obs_office_invite`, шукає активний груповий токен через `get_active_multi_use_token("Наглядач")`; якщо його немає — генерує новий.
  - Відображає посилання, термін дії (`expires_at`), кількість зареєстрованих за ним осіб та кнопки:
    - `🛑 Деактивувати посилання` (`dev_obs_revoke_office_invite:{token}`)
    - `🔄 Перегенерувати нове` (`dev_obs_regen_office_invite`)
    - `⬅️ До списку наглядачів` (`dev_observers_menu`)
- Обробник `developer_observer_revoke_office_invite` (`dev_obs_revoke_office_invite:{token}`):
  - Деактивує токен через `revoke_token(token)`, показує сповіщення `✅ Спільне посилання для офісу деактивовано` і повертає в меню наглядачів.

### 2.3. Реєстрація Наглядача та сповіщення адміна (`bot/handlers.py`, `database/managers.py`)
- У `add_observer` (`database/managers.py`) та `process_registration_full_name` (`bot/handlers.py`):
  - При реєстрації користувача з `role == "Наглядач"` встановлюємо `role = 'Наглядач'` у таблиці `users` (щоб уникнути `NULL` у `users.role`), додаємо в `managers` з `process = 'Наглядач'` та `responsible_uid = manager_id`, викликаємо `use_token(token, user_id)`.
  - Адміністратору (`manager_id`), який створив запрошення, надсилається повідомлення про успішну реєстрацію нового Наглядача з ПІБ, `@username`, Telegram ID та типом посилання (спільне офісне чи одноразове персональне).

## 3. Тестування
- Юніт-тести в `tests/test_observer_office_invite.py`:
  - Генерація та багаторазове використання офісного токена кількома різними `user_id` поспіль.
  - Перевірка, що одноразовий токен блокується після першого використання.
  - Перевірка ручної деактивації (`revoke_token`) спільного токена.
  - Перевірка UI-кнопок меню наглядачів та сповіщення адміністратора при реєстрації наглядача.
