# Дизайн-специфікація: Зміна магазинів керівникам та автоматична прив'язка працівників до Територіалів

**Дата:** 2026-09-03  
**Статус:** Схвалено користувачем  

---

## 1. Мета та опис задачі

Забезпечити надійний механізм зміни закріплених магазинів для керівників та автоматичного перепідпорядкування працівників/стажерів:
1. При зміні магазинів керівника список поточних магазинів повинен одразу відображатися з позначками вибору (`✅`).
2. Запобігти передчасному скиданню прив'язок працівників при простому відкритті меню редагування (перенесення має відбуватися тільки після збереження змін).
3. При відкріпленні магазину від керівника працівники та стажери цього магазину автоматично перепідпорядковуються відповідному Територіалу міста (з урахуванням напрямку ТЗ / ВВ).
4. При закріпленні нового магазину за керівником система запитує підтвердження на переведення співробітників, які наразі перебувають під наглядом Територіала/Адміна (і стажерів, і працівників).
5. При реєстрації нового працівника/стажера у магазині без діючого керівника він автоматично закріплюється за Територіалом міста за напрямком посади (ТЗ або ВВ).

## 2. Архітектура та зміни в базі даних (`database/managers.py`)

### 2.1. Хелпери для пошуку та маршрутизації Територіалів
- **`get_appropriate_territorial_for_user(city: str, role: str) -> int | None`**:
  - Визначає напрямок посади через `get_position_direction(role)` (`"ВВ"` для виробничих посад або `"ТЗ"` для посад торгового залу).
  - Шукає активних територіалів міста (`get_territorials_by_city(city)`).
  - Шукає збіг за `territorial_type == role_direction`.
  - Якщо точного збігу за типом немає — повертає першого активного територіала міста.
  - Якщо в місті немає активних територіалів — повертає `None` (пряме підпорядкування Адміну).

- **`get_manager_by_shop(city: str, shop: str) -> dict | None`**:
  - Шукає активного керівника (`status != 'fired'`), у списку магазинів якого (`shops`) міститься зазначений магазин.

### 2.2. Диференційні функції перепризначення (Delta Reassignment)
- **`reassign_removed_shops_users_to_territorial(city: str, removed_shops: list[str], manager_uid: int) -> int`**:
  - Знаходить користувачів (`status != 'fired'` або активних), у яких `city = city`, `shop IN (removed_shops)` та `manager_id = manager_uid`.
  - Для кожного користувача через `get_appropriate_territorial_for_user(city, role)` призначає `new_manager_id`.
  - Закриває активні сесії спілкування з колишнім керівником.
  - Повертає кількість переприв'язаних користувачів.

- **`count_unassigned_or_territorial_users_in_shops(city: str, shop_names: list[str], exclude_manager_uid: int = None) -> tuple[int, int]`**:
  - Рахує кількість стажерів та працівників у магазинах `shop_names`, які наразі перебувають під опікою Територіала міста або Адміністратора (тобто не мають іншого діючого керівника магазину).
  - Повертає кортеж `(interns_count, workers_count)`.

- **`transfer_shop_users_to_manager(city: str, shop_names: list[str], target_manager_uid: int) -> int`**:
  - Переводить усіх стажерів та працівників із магазинів `shop_names`, які перебували під Територіалом або Адміністратором, під керівництво `target_manager_uid`.

## 3. Логіка взаємодії та інтерфейс (`bot/menus/developer.py`)

### 3.1. Вхід у зміну магазинів (`dev_mgr_change_shops_start`)
- Зчитує поточні магазини керівника з `managers.db`.
- Зберігає у `FSMContext`:
  - `edit_mgr_uid`: ID керівника
  - `manager_city`: місто
  - `original_shops`: список поточних магазинів
  - `selected_shops`: копія поточного списку магазинів
- **НЕ викликає жодних скидань бази на етапі входу.**
- Клавіатура `_build_edit_shops_keyboard` підсвічує вже обрані магазини галочками `✅`.

### 3.2. Перемикання магазинів (`dev_mgr_edit_shop_toggle`)
- Додає/видаляє магазин зі списку `selected_shops`.
- Забезпечує ліміт максимум 5 магазинів.

### 3.3. Скасування змін
- При натисканні «⬅️ Назад» чи «❌ Скасувати» стан FSM очищується, жодних операцій з базою не виконується, повертається картка керівника.

### 3.4. Збереження змін (`dev_mgr_edit_shop_done`)
- Обчислює різницю (delta):
  - `removed_shops = [s for s in original_shops if s not in selected_shops]`
  - `added_shops = [s for s in selected_shops if s not in original_shops]`
- Оновлює базу `managers.db` через `update_manager_shops(manager_uid, city, selected_shops)`.
- Для `removed_shops`: викликає `reassign_removed_shops_users_to_territorial`.
- Для `added_shops`:
  - Перевіряє кількість людей під Територіалом через `count_unassigned_or_territorial_users_in_shops`.
  - Якщо `interns + workers > 0`: показує діалог підтвердження:
    *«✅ Магазини оновлено: ...\n👥 У доданих магазинах знайдено X стажерів та Y працівників (під Територіалом).\nПеревести їх під керівництво цього керівника?»*
    Кнопки: `[ ✅ Так, перевести ]` (`dev_mgr_tr_yes:{manager_uid}`) та `[ ❌ Ні, залишити як є ]` (`dev_mgr_view:{manager_uid}`).
  - Якщо людей немає — показує алерт про успішне оновлення та повертає картку керівника.

### 3.5. Підтвердження переведення (`dev_mgr_transfer_shops_yes`)
- Викликає `transfer_shop_users_to_manager(city, added_shops, manager_uid)` для переведення і стажерів, і працівників.
- Виводить сповіщення `✅ Переведено X співробітників під керівництво!` та оновлює картку керівника.

## 4. Автоматична прив'язка при реєстрації (`bot/handlers.py`)

Під час завершення реєстрації співробітника:
1. Перевіряється наявність діючого керівника для обраного магазину через `get_manager_by_shop(city, shop)`.
2. Якщо керівник є ➔ призначається `manager_id = manager["uid"]`.
3. Якщо керівника в магазині немає ➔ викликається `get_appropriate_territorial_for_user(city, role)` і встановлюється `manager_id = territorial_uid`.
4. Якщо в місті немає активного Територіала ➔ `manager_id = None` (підпорядкування Адміну).

## 5. План тестування та валідація

1. Тест ініціалізації: відкриття зміни магазинів зберігає поточні магазини з `✅` без змін у БД.
2. Тест скасування: вихід без збереження не переносить жодних користувачів.
3. Тест відкріплення магазину: видалення одного магазину зі списку трьох переносить лише співробітників цього магазину до відповідного Територіала (з перевіркою ВВ / ТЗ).
4. Тест додавання магазину: додавання нового магазину з працівниками пропонує переведення і при натисканні «Так» успішно переводить їх.
5. Тест реєстрації: новий стажер у магазині без керівника автоматично отримує `manager_id` Територіала міста за напрямком посади.
