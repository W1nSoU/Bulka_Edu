## 1. Архітектура та межі компонентів

Система складається з одного `asyncio`-процесу Python, що поєднує Telegram-бота та локальний веб-сервер зі спільним рушієм гри та БД `SQLite (WAL)`:

1. **Bot Engine (`bot/`):**
   - `aiogram 3` (long-polling — працює через вихідні HTTPS-запити з MacBook без вебхуків, доменів чи тунелів).
   - Тонкий клієнт **Telegram Bot API 10.4 HTML Widgets** (`aiohttp`): прямі виклики `sendWidget`, `editMessageWidgetData`, `answerWidgetQuery` та обробка `widget_query` updates.
   - Уся торгівля, створення/вступ у синдикати, призначення ролей, синергія та таємне голосування відбуваються **виключно в Telegram-боті**.
   - Резервний `/legacy`-режим (звичайні inline-кнопки Telegram), якщо у когось із гостей не оновлений клієнт Telegram під Bot API 10.4.

2. **Web Server (`web/` — `FastAPI` + `WebSocket` на `http://localhost:8000`):**
   - **`/screen` (Вкладка проектора — суто графік):** повноекранний (`100vw × 100vh`) **1-секундний свічний графік у класичній білій темі TradingView 1:1** (`Lightweight Charts 4.x`, збережений локально без CDN). На `/screen` немає жодних кнопок торгівлі чи адмін-елементів. При виборі нової команди/спікера (та при оновленні сторінки під час старту нового пітчу) графік починається строго з **`1.000`**.
   - **`/admin` (Пульт адміністратора — окрема вкладка):** панель керування ведучого (на ноутбуці або планшеті по локальному Wi-Fi). Містить перемикач етапів, вибір команди + спікера, запуск/зупинку графіка, `Margin Call ВГОРУ / ВНИЗ`, фіксацію перемоги `LONG WIN / SHORT WIN`, «Купівлю людини», керування Раундами 2–4. Ключові кнопки (стоп графіка, Margin Call, фініш пітчу) також продубльовані в адмін-меню Telegram-бота.
   - **`/board` (Окремий екран проектора для пауз і шоу-раундів):** показує QR-код підключення до бота, оголошення кризи та таймер у Раунді 2, дуель `Split or Steal` + ставки Polymarket у Раунді 3 та фінальний лідерборд із феєрверком у Акті III.

3. **Game Engine & Persistence (`engine/` + `db/`):**
   - `MarketEngine`: тиковий цикл `1 Гц`, розрахунок OHLC-свічок, обсягу (`volume`), ціновий вплив угод, ізольована маржа, ліквідації та `Margin Call`.
   - `LedgerDB` (`SQLite WAL`): атомарні транзакції гаманців, позицій, команд, ролей, альянсів та свічок.

```
Telegram Apps (35-45 гостей)
   │  long-polling + sendWidget / editMessageWidgetData / widget_query
   ▼
bot/ (aiogram 3 + Bot API 10.4 client)
   │
   ├──► engine/market.py (1s candles, P0=1.000, isolated margin, PnL, Margin Call)
   ├──► engine/game.py   (state machine: LOBBY → LOCK → TRADING → SYNERGY → DUEL → FINALE)
   └──► db/sqlite.py     (WAL transactions, wallets, syndicates, positions, candles)
   │
   │  WebSocket push (candles, status, admin state, board events)
   ▼
web/ (FastAPI)
   ├── /screen  (окрема вкладка проектора: СУТО світлий TradingView 1с графік)
   ├── /admin   (окрема вкладка ведучого: пульт керування грою)
   └── /board   (окрема вкладка для QR, кризи, Split or Steal та лідерборду)
```

## 2. Візуал проектора `/screen` (TradingView White Theme 1:1)

Графік на `/screen` жорстко дотримується класичного світлого стилю TradingView:
- **Фон та сітка:** чисто-білий фон (`#FFFFFF`), тонка пунктирна сітка (`#E6E9F0`), темно-графітові підписи осей (`#131722`).
- **Свічки:** 1-секундний таймфрейм (`1с`), бичачі `#089981`, ведмежі `#F23645` із чіткими тінями.
- **Гістограма обсягу (`HistogramSeries`):** напівпрозорі стовпчики знизу графіка (`rgba(8,153,129,0.35)` / `rgba(242,54,69,0.35)`), займають нижні ~22% області.
- **Верхня легенда зліва:**
  - Рядок символу й OHLC: `[Іконка] Синдикат «Назва» / Спікер · 1с · FOCUS`, `ВІДК`, `МАКС`, `МІН`, `ЗАКР`, зміна (`+0,000 (+0,00%)`).
  - Котирування: червоний прямокутник `SHORT` (bid) і синій `LONG` (ask).
  - Рядок `Обсяг · FD` (динамічний обсяг поточної свічки/пітчу).
- **Права шкала ціни та нижня панель часу:** кольорова плашка поточної ціни на правій осі, мітки часу (`HH:MM:SS`) та індикатор `UTC+2` і статусу `● LIVE 1с` / `⏸ ЗУПИНЕНО` у нижньому рядку (без перекриття верхнього OHLC).
- **Початкова ціна:** кожна нова торгова сесія (обрана команда + спікер) починається строго з `1.000`. Оновлення сторінки `/screen` або перехід до нового спікера одразу відображає свіжий графік поточної сесії від `1.000`.

## 3. Telegram Bot API 10.4 HTML Widgets (`core.telegram.org/bots/widgets`)

Ураховуються всі жорсткі обмеження специфікації Bot API 10.4:
- **Розмір шаблону:** <= `32 KB` raw та <= `4 KB` gzip (ціль: `< 2.5 KB` gzip на віджет).
- **Стан (`chat_data`):** <= `1024` байти JSON на повідомлення; оновлення приходить у `TelegramWidget.onEvent('chatDataChanged', ...)`.
- **Заборонені теги:** `<input>`, `<textarea>`, `<select>` вирізаються Telegram-ом — усі вибори у віджетах реалізовано через компактні кнопки та сегментовані перемикачі, а текстове введення (назва нового синдикату при створенні) робиться через 1 стандартне повідомлення в чат бота.
- **Обхід ліміту Telegram (~30 req/s):** `editMessageWidgetData` для живого PnL шлеться пакетами **раз на 2.5 секунди лише гравцям із відкритою позицією**, а при відкритті/закритті угоди, ліквідації, `Margin Call` або зміні фази гри — миттєво.

### Набір віджетів учасника (відправляються через `sendWidget`)
1. **Стан `PRE_MARKET_LOCK` («Етап 1 розпочато»):**
   - Повний банер: *«⏳ Скоро почнуться торги. Усі дії тимчасово заблоковані»*. Будь-які старі кнопки чи `widget_query` відхиляються сервером із коротким тостом.
2. **Вкладка «Синдикат» (`HubWidget`):**
   - Якщо гравець без команди: кнопка «➕ Створити синдикат» (запитує назву в чаті -> гравець стає лідером) або «📷 Приєднатися за кодом» / перехід за deep-link QR лідера (`t.me/<bot>?start=syn_<code_4digit>`).
   - Якщо гравець у команді: назва синдикату, сумарний капітал усіх учасників столу, список учасників із поточними ролями (`👑 СЕО`, `🤝 Дипломат`, `📈 Аналітик`, `👤 Учасник`), кнопка показу QR лідера для запрошення та панель призначення ролей (доступна лідеру / СЕО, вибір учасника й ролі кнопками прямо у віджеті).
3. **Торговий віджет (`TradingWidget`, Раунд 1 та бліц Раунду 4):**
   - Заголовок: поточний спікер і команда, жива ціна, баланс гравця.
   - **Коли угоди немає:** вибір напрямку (`🟢 LONG` / `🔴 SHORT`), вибір ізольованої маржі (`100k` / `250k` / `500k` / `ALL-IN`), вибір плеча (`x1` / `x3` / `x5` / `x10`), кнопка `Відкрити`. *(Учасники команди спікера бачать інформацію про власний виступ із вимкненими кнопками торгівлі).*
   - **Коли угода відкрита:** блок внизу показує деталі входу (`SIDE xL · Вхід P_entry · Лікв P_liq`), **живий PnL** (`+FD` і `%`), що оновлюється автоматично, та кнопку **«Закрити угоду»**.
4. **Раундові віджети:**
   - **Раунд 2 (`SynergyWidget`):** закріплений за столом ресурс (`Склад`, `Трафік`, `IT`, `Відділ Продажів`, `Безперебійники`, `Виробництво`, `Фінанси`), кнопка показу QR альянсу (`t.me/<bot>?start=ally_<token>`) та 4-значний код.
   - **Раунд 3 (`DuelWidget`):** для двох СЕО на сцені — 2 кнопки (`🤝 ПОДІЛИТИ` / `🥷 ЗАБРАТИ ВСЕ`); для залу — ставки Polymarket (`Обидва поділять`, `Зрада А`, `Зрада Б`, `Обидва вкрадуть`) з фіксованими ставками `100k / 250k / 500k`.

## 4. Економіка, Ізольована маржа та Механіки 4 раундів

### 4.1. Гаманці та капітал Синдикату
- Стартовий баланс кожного учасника: `1,000,000 FD`.
- **Капітал Синдикату = сума особистих балансів усіх поточних гравців команди.**
- **Командні нарахування (бонуси):** діляться порівну (`bonus // N`, залишок від ділення віддається СЕО/спікеру).
- **Командні списання (застави, штрафи, викуп):** списуються пропорційно балансам гравців столу з обмеженням `wallet >= 0` (спочатку перевіряється достатність сумарного капіталу команди).

### 4.2. Математика графіка, Ізольованої маржі та Margin Call (Раунд 1)
- При запуску пітчу команди $S$:
  - Списується застава `500,000 FD` з команди $S$ (якщо капітал команди < `500,000 FD`, застава = весь доступний капітал).
  - Стартова ціна `P₀ = 1.000`.
- **Рух ціни (1с свічки):**
  - Кожної секунди (поки графік не на паузі) додається базовий ринковий шум ($\pm 0.15\% \dots 0.30\%$).
  - При відкритті угоди з маржею $M$ і плечем $L$:
    - Ефективний обсяг $V = M \cdot L$.
    - Миттєвий зсув ціни: $\Delta P = s \cdot P \cdot k \cdot \sqrt{V / 1\,000\,000}$, де $s = +1$ для `LONG`, $s = -1$ для `SHORT`, $k = 0.018$.
    - На баланс команди спікера одразу нараховується роялті **2% від маржі $M$** (`int(M * 0.02)`).
  - Закриття угоди гравцем дає помірний зворотний зсув ($0.5 \cdot \Delta P$).
- **Ізольована маржа та PnL:**
  - При вході з гаманця гравця резервується лише маржа $M$ (інші кошти гравця захищені від ліквідації).
  - Поточний PnL:
    - `LONG`: $\text{PnL} = M \cdot L \cdot \frac{P_{\text{now}} - P_{\text{entry}}}{P_{\text{entry}}}$
    - `SHORT`: $\text{PnL} = M \cdot L \cdot \frac{P_{\text{entry}} - P_{\text{now}}}{P_{\text{entry}}}$
  - Поріг ліквідації:
    - `LONG`: $P_{\text{liq}} = P_{\text{entry}} \cdot \left(1 - \frac{1}{L}\right)$
    - `SHORT`: $P_{\text{liq}} = P_{\text{entry}} \cdot \left(1 + \frac{1}{L}\right)$
  - Якщо `P_now` перетинає `P_liq` (або $\text{PnL} \le -M$), позиція **автоматично ліквідується**: виплата `0`, решта балансу гравця залишається недоторканою.
  - При ручному закритті на баланс повертається $\max(0,\; \text{round}(M + \text{PnL}))$.
- **Margin Call (адмін-кнопка):**
  - `📈 Margin Call ВГОРУ`: миттєво малює свічку з імпульсом $+35\%$ (гарантовано ліквідує відкриті `SHORT` з плечем `x3`, `x5`, `x10` або вище поточного порогу).
  - `📉 Margin Call ВНИЗ`: миттєво малює свічку $-35\%$ (ліквідує відкриті `LONG` з плечем `x3+`).
- **Завершення пітчу ведучим (`LONG WIN` / `SHORT WIN`):**
  - В `/admin` підсвічується лідер ринку (поточна ціна vs `1.000` та сума відкритого/проторгованого обсягу), але фінальне рішення натискає ведучий.
  - Усі відкриті позиції примусово закриваються за поточною ціною.
  - При `LONG WIN`: команді спікера повертається застава `500,000 FD` + премія засновника `+1,000,000 FD`.
  - При `SHORT WIN`: застава `500,000 FD` не повертається і ділиться пропорційно маржі між тими, хто закрився у плюс по `SHORT` (або мав прибуткові `SHORT`-позиції в цьому пітчі).

### 4.3. Раунди 2, 3 і 4
- **Раунд 2 (Синергія):** адміністратор запускає кризу -> кожен Синдикат отримує ресурс і партнерський QR/код -> при скануванні QR або вводі коду іншої команди створюється альянс (максимум 1 альянс на пару або 1 підтверджений партнер на раунд — без подвійного фарму з одним і тим самим столом) -> обом командам нараховується `+1,000,000 FD`. Після закриття раунду адміном команди без жодного альянсу отримують `-200,000 FD`.
- **Раунд 3 (Split or Steal + Polymarket):** адмін обирає 2 команди -> з кожної списується депозит `1,000,000 FD` -> відкриваються таємні кнопки для СЕО дуелянтів та пул ставок Polymarket (чистий Parimutuel: виграшна категорія забирає весь банк протилежних ставок пропорційно своїй ставці) для решти гравців. Розкриття в `/admin` виплачує банк `3,000,000 FD` за матрицею (`50/50` по `1.5M`, зрада `3M / 0`, подвійна зрада `0 / 0`) і розраховує Polymarket-ставки.
- **Раунд 4 («Купівля людини» + Бліц):** в `/admin` кнопка **«Купівля людини»** відкриває 3-кроковий вибір: `Команда-донор` → `Гравець` → `Цільова команда (покупець)`. Перевіряється наявність `1,500,000 FD` у покупця (і відображається підказка, якщо покупець у топ-3, з можливістю адміна підтвердити виняток). Після підтвердження списується `1,500,000 FD` з покупця, а гравець разом зі своїм поточним гаманцем переноситься в нову команду.

## 6. Обробка помилок та верифікація

- **Атомарність та захист від подвійного кліку:** кожна зміна балансу й операція відкриття/закриття угоди виконується всередині транзакції `BEGIN IMMEDIATE` в SQLite. Повторні кліки впродовж <300 мс або після закриття позиції безпечно відхиляються.
- **Перезавантаження браузера або падіння Wi-Fi:** усі свічки поточної сесії зберігаються в `candles` — при F5 на `/screen` графік миттєво відновлює історію поточної сесії, а при виборі нового спікера чистить полотно і стартує з `1.000`.
- **Telegram Rate Limit та застарілі клієнти:** черга оновлень `editMessageWidgetData` обмежена до 20 запитів/сек і оновлює лише відкриті позиції раз на 2.5с. Якщо Telegram поверне помилку підтримки віджета або користувач натисне `/legacy`, бот перемикає його на класичну inline-клавіатуру без переривання гри.
- **План тестування:** автоматизовані `pytest`-тести на всю математику маржі/раундів, 40-користувацький нагрузочний тест перед 28 листопада та ручний прогін із реальними смартфонами у Telegram (перевірка `sendWidget` і `editMessageWidgetData` на iOS/Android).
