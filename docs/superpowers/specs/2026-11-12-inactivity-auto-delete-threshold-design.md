# Специфікація: Зміна порогу автоматичного видалення неактивних стажерів з 3 на 7 робочих днів

## 1. Огляд та мета
Наразі система автоматично відраховує та видаляє стажерів з бази даних після 3 робочих днів неактивності. Через реальні операційні процеси в магазинах (стажери виходять у зміну, затримуються з проходженням тестування в телефоні або керівники не встигають вчасно перевести їх у статус «Працівник»), 3 робочі дні виявилися занадто коротким терміном, що призводить до випадкового видалення діючих співробітників.

**Мета:** Збільшити поріг неактивності до **7 робочих днів** (вихідні дні субота та неділя не враховуються) та зробити цей параметр повністю конфігурованим через змінну оточення `INACTIVE_DAYS_THRESHOLD` (зі значенням за замовчуванням `7`).

---

## 2. Зміни в архітектурі та компонентах

### 2.1. Конфігурація середовища (`.env.example` та `bot/config.py`)
- У `.env.example` встановити:
  ```ini
  INACTIVE_DAYS_THRESHOLD=7
  ```
- У `bot/config.py` встановити дефолтне значення `7`:
  ```python
  INACTIVE_DAYS_THRESHOLD = int(os.getenv("INACTIVE_DAYS_THRESHOLD", "7"))
  ```

### 2.2. Сервіс нагадувань та фонових завдань (`bot/services/reminders.py`)
- Замінити жорстко закодоване `INACTIVE_DAYS_THRESHOLD = 3` на імпорт або використання значення з `bot.config`:
  ```python
  from bot.config import INACTIVE_DAYS_THRESHOLD
  ```
- У фоновому завданні `check_and_send_reminders_task` передавати конфігурований поріг:
  ```python
  inactive_to_delete = await get_inactive_interns_for_auto_delete(days=INACTIVE_DAYS_THRESHOLD)
  ```
- Оновити текст повідомлення керівнику при видаленні стажера:
  динамічно підставляти `{INACTIVE_DAYS_THRESHOLD}` замість захардкодженного числа `3`:
  ```python
  f"<i>Стажер був неактивний понад {INACTIVE_DAYS_THRESHOLD} робочих днів (субота та неділя не враховувалися) "
  f"і був автоматично відрахований з навчальної програми.</i>"
  ```

### 2.3. База даних та розрахунок робочих днів (`database/users.py`)
- У функції `get_business_days_cutoff`:
  Оновити дефолтне значення аргументу `business_days` з `3` на `7`:
  ```python
  def get_business_days_cutoff(now: Optional[datetime] = None, business_days: int = 7) -> datetime:
  ```
- У функції `get_inactive_interns_for_auto_delete`:
  Оновити дефолтне значення аргументу `days` з `3` на `7`:
  ```python
  async def get_inactive_interns_for_auto_delete(days: int = 7) -> list[dict]:
  ```

---

## 3. Обробка граничних випадків та безпека
1. **Вихідні дні:** Механізм розрахунку робочих днів (`get_business_days_cutoff`) уже враховує суботи та неділі (вони виключаються з підрахунку). Зміна порогу до 7 робочих днів означає фактично 9-11 календарних днів неактивності, що дає достатньо часу для розбору ситуації на точці.
2. **Захист працівників та привілейованих ролей:** Користувачі зі статусом `status == 'Працівник'` або керівними ролями продовжують безумовно ігноруватися алгоритмом автовидалення.
3. **Зворотна сумісність:** Функції підтримують передачу довільної кількості днів через параметр `days`, тому існуючі виклики не зламаються.
