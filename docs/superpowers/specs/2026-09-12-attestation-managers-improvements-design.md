# Дизайн: Вдосконалення атестації керівників (фільтрація, моніторинг, детальний звіт)

## 1. Контекст та мета
У модулі корпоративної атестації для цільової групи **«👔 Керівники»** необхідно:
1. Відображати для вибору та реєстрації виключно керівників магазинів, відсікаючи адміністраторів, розробників, наглядачів і територіалів.
2. На екрані активної хвилі для керівників виводити безпосередньо список керівників (ПІБ + магазин) із кнопками перегляду успішності кожного керівника, замість списку магазинів.
3. У звіті Excel (XLSX) формувати:
   - Аркуш 1: «Зведений рейтинг керівників» (ПІБ, магазин, бали, %, статус).
   - Аркуші 2..N: окремий аркуш на кожного керівника з детальним аудитом запитань, обраних та правильних відповідей.

---

## 2. Архітектура та компоненти змін

### 2.1. Фільтрація керівників (`bot/menus/attestation.py`)
- **Функція `_get_active_managers_list()`:**
  - Фільтрує список з `get_all_managers()`:
    - Залишає лише записи, де `process in ('Керівник', 'Керівник Стажер')` та `status != 'fired'`.
    - Виключає будь-яких користувачів з `process in ('Developer', 'Адміністратор', 'Наглядач', 'Територіал')`.
    - Виключає користувачів з непорожнім полем `territorial_type`.
    - Виключає ID, що входять до списку розробників (`MAIN_DEVELOPER_ID`, `DEVELOPER_IDS`).
- **Відображення кнопок у пікері (`_render_managers_picker`):**
  - Отримує назву основного магазину керівника (`m.get("shops")`).
  - Текст кнопки: `{mark}{name} ({shop})` (обрізка за потреби для коректного рендерингу Telegram inline button).
- **Збір учасників (`_collect_eligible_participants`):**
  - Застосовує аналогічну сувору фільтрацію для `target_type == 'managers'`.

### 2.2. Моніторинг активної хвилі керівників (`dev_att_active_wave_handler`)
- При `wave['target_type'] == 'managers'`:
  - Заголовок: `👔 <b>Керівники хвилі (натисніть для деталей):</b>`
  - Отримання списку учасників хвилі та їхніх спроб.
  - Інлайн-кнопки по керівниках із пагінацією (по 6-8 на сторінку):
    - `[ 🟢/🔴/⏳/💤 ПІБ — Магазин (Результат) ]`
    - Callback: `dev_att_mgr_dt:{wave_id}:{user_id}`
- **Хендлер деталей керівника (`dev_att_manager_details_handler`):**
  - Відображає картку керівника: ПІБ, магазин, статус, бали, відсоток, час проходження, дата завершення.
  - Якщо тест не складено або таймаут — кнопка надання перездачі `[ 🔄 Дозволити перездачу ]` (`dev_att_grant_retake_mgr:{wave_id}:{user_id}`).
  - Кнопка повернення до списку керівників хвилі `[ 🔙 До списку керівників ]`.

### 2.3. Генерація Excel-звіту для керівників (`bot/services/attestation_excel.py`)
- У функції `generate_attestation_results_xlsx(wave_id)`:
  - Якщо `wave['target_type'] == 'managers'`:
    - **Аркуш 1 («Зведений рейтинг керівників»):**
      - Заголовок та метадані хвилі.
      - Таблиця: `№`, `ПІБ керівника`, `Магазин`, `Набрано балів`, `Макс. балів`, `% успішності`, `Вердикт`, `Дата здачі`.
    - **Аркуші 2..N (по одному аркушу на кожного керівника):**
      - Назва аркуша: санітизоване ПІБ керівника (унікальне, до 31 символу).
      - Заголовковий блок: ПІБ, Магазин, Дата, Бали, Відсоток, Статус.
      - Таблиця відповідей:
        `№` | `Запитання` | `Відповідь керівника` | `Правильна відповідь` | `Вердикт` | `Бали` | `Пояснення`
      - Запитання та варіанти завантажуються за `questions_order_json` та `answers_json` спроби керівника.

## 3. Обробка помилок та граничні випадки
1. **Керівник без спроби (не розпочинав):**
   - У зведеному аркуші вердикт «💤 Не розпочато».
   - Окремий аркуш створюється з позначкою, що тест ще не розпочато, або пропускається, якщо відповідей немає.
2. **Керівник без магазину:**
   - Дефолтне значення назви магазину: «Не вказано».
3. **Пагінація кнопок у боті:**
   - Коректна навігація між сторінками списку керівників активної хвилі.

## 4. План тестування
- Unit-тести:
  - Тест фільтрації керівників (виключення адмінів, територіалів, наглядачів).
  - Тест генерації Excel для хвилі керівників: перевірка наявності зведеного аркуша та аркушів по кожному керівнику з питаннями та відповідями.
  - Тест відкриття картки керівника та видачі перездачі.
