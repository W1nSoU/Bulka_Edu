# Дизайн-документ: Підсистема «Розсилки» та Модуль «Опитування» для мережі BULKA

**Дата**: 2026-09-11  
**Статус**: Схвалено (готується до впровадження)  
**Ціль**: Реорганізація панелі адміністратора з винесенням меню «Розсилки» (куди переноситься «Ознайомлення з матеріалами») та впровадження повного циклу проведення корпоративних опитувань з похвильовою розсилкою, розумними нагадуваннями, live-статистикою та аналітичними XLSX-звітами.

---

## 1. Загальний огляд та цілі

1. **Реорганізація панелі адміністратора**:
   * Додати пункт **«📨 Розсилки»** у головну панель адміністратора (`_admin_cho_keyboard`).
   * Перенести **«📋 Ознайомлення з матеріалами»** з меню «📊 Аналітика» у меню «📨 Розсилки».
   * Додати пункт **«📝 Опитування»** у меню «📨 Розсилки».
2. **Модуль «Опитування»**:
   * Створення опитувань за гнучким шаблоном (питання з варіантами вибору або з вільною текстовою відповіддю).
   * Попередній перегляд (симуляція проходження) та підтвердження шаблону.
   * Таргетинг аудиторії: мультиселект посад/статусів (Працівники, Стажери, Керівники, Наглядачі) та географії (Усі міста або конкретне місто).
   * Похвильова безпечна відправка (хвилі по 50 осіб з випадковим інтервалом 5-10 хвилин і мікропаузами між повідомленнями).
   * Інтерактивне проходження в Telegram: анонімний лейбл для працівника, інлайн-кнопки для вибору та текстові повідомлення для вільних відповідей.
   * Розумний планувальник нагадувань: до 3 нагадувань, випадковий інтервал 3-7 годин, робоче вікно 09:00-19:00 (перенесення на 10:30 наступного дня), максимальний термін життя опитування 72 години.
   * Аналітика та XLSX-експорт: зведений аркуш із розподілом та % відповідей по варіантах + окремі аркуші по магазинах із ПІБ та відповідями працівників.
   * Права доступу: виключно для Адміністраторів.

## 2. Структура бази даних (Database Schema)

Нові таблиці створюються в системній БД (`DB_PATH`, `bulka.db` / `users.db`):

```sql
-- Головна таблиця опитувань
CREATE TABLE IF NOT EXISTS surveys (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    raw_template TEXT NOT NULL,
    created_by INTEGER NOT NULL,
    target_roles TEXT NOT NULL, -- JSON-масив: ["Працівник", "Стажер", "Керівник", "Наглядач"]
    target_city TEXT, -- NULL для "Усі міста" або назва міста
    status TEXT NOT NULL DEFAULT 'draft', -- draft | broadcasting | active | closed
    total_recipients INTEGER DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    launched_at TIMESTAMP,
    closed_at TIMESTAMP
);

-- Таблиця питань опитування
CREATE TABLE IF NOT EXISTS survey_questions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    survey_id INTEGER NOT NULL,
    question_idx INTEGER NOT NULL,
    text TEXT NOT NULL,
    question_type TEXT NOT NULL, -- 'choice' | 'text'
    options_json TEXT, -- JSON-масив: ["Варіант 1", "Варіант 2", ...]
    FOREIGN KEY (survey_id) REFERENCES surveys(id) ON DELETE CASCADE,
    UNIQUE (survey_id, question_idx)
);

-- Таблиця отримувачів опитування
CREATE TABLE IF NOT EXISTS survey_recipients (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    survey_id INTEGER NOT NULL,
    user_id INTEGER NOT NULL,
    wave_number INTEGER DEFAULT 1,
    status TEXT NOT NULL DEFAULT 'pending', -- pending | sent | in_progress | completed | failed
    current_q_idx INTEGER DEFAULT 0,
    sent_at TIMESTAMP,
    completed_at TIMESTAMP,
    reminders_sent INTEGER DEFAULT 0,
    next_reminder_at TIMESTAMP,
    last_reminder_at TIMESTAMP,
    FOREIGN KEY (survey_id) REFERENCES surveys(id) ON DELETE CASCADE,
    UNIQUE (survey_id, user_id)
);

-- Таблиця відповідей співробітників
CREATE TABLE IF NOT EXISTS survey_answers (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    survey_id INTEGER NOT NULL,
    user_id INTEGER NOT NULL,
    question_idx INTEGER NOT NULL,
    answer_text TEXT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (survey_id) REFERENCES surveys(id) ON DELETE CASCADE,
    UNIQUE (survey_id, user_id, question_idx)
);
```

## 3. Парсер шаблону опитування

Адміністратор вводить опитування у текстовому форматі:
```text
1. Як ви оцінюєте графік змін?
а. Зручний
б. Потребує корекції
в. Незручний

2. Чи вистачає розхідних матеріалів на зміні?
а. Так, завжди
б. Інколи не вистачає

3. Ваші побажання щодо покращення процесів (вільна відповідь)
```

### Правила парсингу:
1. Номер питання: рядок, що починається з цифри та крапки (`^\d+\.\s*(.+)$`).
2. Якщо в тексті питання є маркер `(вільна відповідь)` (регістронезалежно) — `question_type = 'text'`, варіанти відсутні.
3. Варіанти вибору: рядки, що починаються з літери українського або латинського алфавіту з крапкою чи дужкою (`^[а-яa-z]\.?\)\s*(.+)$`).
4. Валідація:
   * Опитування повинно містити щонайменше 1 питання.
   * Кожне питання з вибором повинно містити щонайменше 2 варіанти відповіді.
   * У разі помилки користувачу вказується номер некоректного питання та пропонується надіслати виправлений текст.

## 4. Сценарій взаємодії адміністратора (FSM Creation Wizard)

1. **Меню `developer_menu`**:
   * Кнопка `[ 📨 Розсилки ]` веде до підменю `dev_broadcasts_menu`.
2. **Меню `dev_broadcasts_menu`**:
   * `[ 📋 Ознайомлення з матеріалами ]` (`dev_an_ack_menu`).
   * `[ 📝 Опитування ]` (`dev_surveys_menu`).
   * `[ 🔙 Назад ]` (`developer_menu`).
3. **Меню `dev_surveys_menu`**:
   * `[ ➕ Створити опитування ]` (`dev_survey_create_start`).
   * `[ 📊 Список опитувань ]` (`dev_surveys_list:0`).
   * `[ 🔙 Назад ]` (`dev_broadcasts_menu`).
4. **Кроки створення (`SurveyCreationStates`)**:
   * `waiting_for_title`: очікування тексту теми/назви.
   * `waiting_for_template`: очікування тексту запитань за шаблоном.
   * Парсинг -> показ прев'ю результатів парсингу:
     * Кнопка `[ 👁 Переглянути вигляд ]` (симуляція запитання 1).
     * Кнопка `[ ➡️ Далі (вибір аудиторії) ]`.
     * Кнопка `[ ❌ Скасувати ]`.
   * `selecting_roles`: інлайн-кнопки з галочками (мультиселект):
     * `[ ☑️/⬜️ Працівники ]`, `[ ☑️/⬜️ Стажери ]`, `[ ☑️/⬜️ Керівники ]`, `[ ☑️/⬜️ Наглядачі ]`.
     * Кнопка `[ ➡️ Продовжити ]`.
   * `selecting_city`:
     * `[ 🏙 Усі міста ]` або вибір зі списку існуючих міст.
   * **Екран підтвердження**:
     * Відображається кількість знайдених діючих користувачів (без видалених), розрахована кількість хвиль (по 50 чол.).
     * Кнопка `[ 🚀 Запустити розсилку ]`.

## 5. Механізм похвильової розсилки (Wave Broadcaster)

1. **Формування хвиль**:
   * Всі відібрані користувачі розбиваються на групи по 50 осіб (`wave_number` від 1 до N).
   * Записи створюються в `survey_recipients` зі статусом `pending`.
2. **Відправка**:
   * Перша хвиля стартує негайно після підтвердження.
   * Всередині хвилі: відправка з мікропаузою `asyncio.sleep(0.08)` між користувачами.
   * Між хвилями: випадкова пауза `random.randint(300, 600)` секунд (5–10 хвилин).
   * Якщо користувача видалено з бота чи заблоковано бота — фіксується помилка, розсилка продовжується без збоїв.

## 6. Проходження опитування користувачем

1. **Запрошення**:
   * Повідомлення:
     > 📋 **Нове опитування мережі BULKA**  
     > **«{title}»**  
     > ───────────────────  
     > *🔒 Це опитування є повністю анонімним. Ваші щирі відповіді допоможуть нам зробити умови праці та процеси ще зручнішими!*  
     > *⏳ Проходження займе не більше 2-3 хвилин.*
   * Кнопка: `[ 📝 Пройти опитування ]` (`survey_start:{survey_id}`).
2. **Процес опитування**:
   * Стан FSM `SurveyTakingState:answering`.
   * Для запитання з варіантами: інлайн-кнопки для кожного варіанту (`survey_ans:{survey_id}:{q_idx}:{opt_idx}`).
   * Для вільної відповіді: текстове поле, очікування текстового повідомлення від користувача.
   * Збереження кожної відповіді в `survey_answers`.
   * Оновлення поточного індексу питання `current_q_idx` у `survey_recipients`.
3. **Фініш**:
   * Оновлення статусу в `survey_recipients` на `completed`, фіксація `completed_at`.
   * Повідомлення:
     > 🎉 **Дякуємо за участь в опитуванні!**  
     > *Ми цінуємо вашу думку та щодня стараємось, аби сімʼя BULKA ставала ще кращою.* 🥐✨

## 7. Планувальник нагадувань (Reminders Scheduler)

1. **Цільова аудиторія**:
   * Отримувачі опитування зі статусом `sent` або `in_progress` (хто не має `completed`).
   * Менше 3 надісланих нагадувань (`reminders_sent < 3`).
   * Минуло менше 72 годин від старту опитування (`launched_at + 72h`).
2. **Розрахунок часу наступного нагадування**:
   * При відправці первинного повідомлення або попереднього нагадування призначається `next_reminder_at`:
     * Поточний час + випадковий інтервал від 3 до 7 годин (`random.randint(180, 420)` хвилин).
     * Якщо час потрапляє після 19:00 або до 09:00 — автоматично переноситься на **10:30 наступного дня**.
3. **Шаблони нагадувань**:
   * **Нагадування 1**: «Привіт! 🥐 Нагадуємо про опитування "{title}". Твоя думка дуже важлива для нас! Проходження займе всього 2-3 хвилинки.»
   * **Нагадування 2**: «Привіт знову! ☕️ Ми все ще чекаємо на твої відповіді в опитуванні "{title}". Допоможи нам покращити роботу в магазинах BULKA!»
   * **Нагадування 3**: «Останнє нагадування! ⏳ Опитування "{title}" незабаром завершиться. Поділись своїми думками — це повністю анонімно!»
   * Кожне нагадування містить кнопку: `[ 📝 Пройти опитування ]`.
4. **Фонова задача**:
   * Періодичний асинхронний перевірочний цикл (наприклад, кожні 5 хвилин), що перевіряє `next_reminder_at <= NOW()` і розсилає належні нагадування.

## 8. Картка опитування та генерація XLSX-звіту

### Картка в боті:
* Назва опитування, дата запуску, автор.
* Аудиторія: Цільові ролі, Місто.
* Прогрес: Отримали: **N**, Відповіли: **M** (відсоток).
* Кнопка: `[ 📥 Вивантажити результати (XLSX) ]` (`survey_export_xlsx:{survey_id}`).

### Структура XLSX-звіту:
Файл формується бібліотекою `openpyxl`:
1. **Вкладка 1: «Загальні результати»**:
   * Загальна статистика: назва, дата запуску, охоплення, кількість відповідей.
   * Блоки по кожному питанню:
     * Для питань із варіантами: таблиця варіантів, кількість голосів, відсоткова частка (`X голосів (Y.Y%)`).
     * Для відкритих питань: кількість отриманих розгорнутих відповідей.
2. **Вкладки по кожному магазину** (назва вкладки — код магазину, наприклад `b-12`, `b-14`):
   * Колонки:
     * `ПІБ співробітника` | `Посада` | `Питання 1` | `Питання 2` | ... | `Дата проходження`
   * Відповіді з вибором позначаються текстом або `X`, відкриті — повним текстом співробітника.
   * Стилізація у фірмових кольорах BULKA (заголовки, сітка, автопідбір ширини колонок).

## 9. План верифікації та тестування

1. **Unit-тести парсера**:
   * Тест на розпізнавання питань з варіантами вибору.
   * Тест на розпізнавання відкритих питань `(вільна відповідь)`.
   * Тест валідації некоректного формату.
2. **Тести бази даних**:
   * Створення опитування, додавання питань, реєстрація отримувачів.
   * Збереження відповідей, розрахунок агрегатів (% та кількості голосів).
3. **Тести планувальника нагадувань**:
   * Розрахунок часу нагадування з дотриманням вікна 09:00-19:00 та перенесенням на 10:30.
   * Зупинка нагадувань після 3 разів або після 72 годин.
4. **Тест генерації XLSX**:
   * Створення звіту з тестовими даними кількох магазинів, перевірка структури аркушів та обчислення відсотків.
