# Дизайн-документ: Навчання для керівників та роль «Керівник Стажер» (Пункт 6)

## 1. Огляд та мета
Метою цієї задачі є запровадження навчального процесу для новопризначених керівників магазинів.
Кожен новий керівник додається в бот у статусі «Керівник Стажер» та проходить навчальний курс, закріплений за посадою «Керівник».
Проходженням навчання керує закріплений Територіальний керівник. По завершенню навчання Територіал отримує запит на переведення керівника в повноцінний статус «Керівник».

---

## 2. Модель даних та ролі (`database/managers.py`, `database/users.py`)

### 2.1. Таблиця `managers`
- Значення поля `process`:
  - `'Керівник Стажер'` — новий керівник на етапі навчання.
  - `'Керівник'` — повноцінний керівник після затвердження Територіалом.
  - `'Територіал'`, `'Developer'`, `'Наглядач'`.
- Оновлення `is_manager_user(user_id)`:
  - Перевіряє `process IN ('Керівник', 'Керівник Стажер')`. Обидва статуси мають однаковий повний доступ до адміністрування стажерів.
- Нові функції помічники в `database/managers.py`:
  - `is_manager_trainee(user_id: int) -> bool`: повертає `True`, якщо `process == 'Керівник Стажер'`.
  - `promote_manager_trainee(uid: int) -> bool`: встановлює `process = 'Керівник'` у таблиці `managers` та `process = 'Працівник'` у таблиці `users`.
  - `get_manager_trainees_by_territorial(territorial_uid: int) -> list[dict]`: повертає список стажерів-керівників певного територіала.

### 2.2. Таблиця `users`
- При створенні нового керівника запис у таблиці `users` має:
  - `role = 'Керівник'`
  - `process = 'Стажер'`
  - `day = 1`
- Це дає змогу використовувати наявний механізм проходження навчальних днів та тестувань без створення дублюючих таблиць або моделей.

## 3. Інтерфейс у Telegram-боті

### 3.1. Панель керівника (`bot/keyboards.py`, `bot/menus/manager.py`)
- У клавіатуру `manager_menu_keyboard()` на самий верх (першим рядком) додається кнопка:
  `[ 📚 Навчання ]` (callback: `mgr_learning_menu` або `continue_learning`).
- Кнопка залишається доступною завжди (як для `Керівник Стажер`, так і для `Керівник`), щоб можна було переглядати матеріали в будь-який момент.

### 3.2. Головне меню (`bot/keyboards.py`)
- Для керівників (як `Керівник`, так і `Керівник Стажер`) відображається кнопка `[ 👑 Панель керівника ]` та `[ 👤 Профіль ]`.

## 4. Логіка завершення навчання та переведення

### 4.1. Тригер фінального тесту (`days/day_handlers.py` / `bot/services/learning_progress.py`)
- Коли користувач із роллю `role == 'Керівник'` успішно складає тест останнього навчального дня:
  - Перевіряється, чи користувач є в базі `managers` як `Керівник Стажер`.
  - Знаходиться закріплений `responsible_uid` (Територіал або Адміністратор).
  - Якщо знайдено `responsible_uid`, бот надсилає йому інтерактивне повідомлення:
    ```
    🎓 Керівник-стажер <b>{full_name}</b> ({city}, {shops}) успішно завершив(-ла) всі дні навчальної програми керівника!

    Бажаєте перевести його/її в статус повноцінного <b>Керівника</b>?
    ```
    Кнопки:
    - `[ ✅ Перевести у «Керівник» ]` (`dev_promote_mgr:{uid}`)
    - `[ ⏳ Залишити «Керівник Стажер» ]` (`dev_keep_mgr_trainee:{uid}`)

### 4.2. Обробка рішення Територіала
- При натисканні `[ ✅ Перевести у «Керівник» ]`:
  - Викликається `promote_manager_trainee(uid)`.
  - Повідомлення Територіала оновлюється на:
    `✅ Керівника <b>{full_name}</b> успішно переведено в статус <b>Керівник</b>.`
  - Керівнику надсилається сповіщення:
    `🎉 <b>Вітаємо!</b> Ваш територіальний керівник підтвердив завершення навчання. Вам присвоєно статус <b>Керівник</b>!`
- При натисканні `[ ⏳ Залишити «Керівник Стажер» ]`:
  - Повідомлення Територіала оновлюється на:
    `⏳ Керівник <b>{full_name}</b> залишається в статусі <b>Керівник Стажер</b>.`

---

## 5. План тестування та валідації
1. **Тест ролей:** Перевірити, що `is_manager_user()` повертає `True` для `'Керівник Стажер'` і `'Керівник'`.
2. **Тест клавіатур:** Перевірити наявність кнопки `[ 📚 Навчання ]` у верхній частині `manager_menu_keyboard()`.
3. **Тест життєвого циклу:**
   - Створення керівника зі статусом `Керівник Стажер`.
   - Проходження навчальних днів та тестів для ролі `'Керівник'`.
   - Отримання та обробка колбеку `dev_promote_mgr:{uid}` Територіалом.
   - Оновлення статусу на `'Керівник'` та доставка повідомлення керівнику.
