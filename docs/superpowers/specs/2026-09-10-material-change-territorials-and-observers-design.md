# Специфікація: Сповіщення про зміну навчальних матеріалів для Територіалів та виключення Наглядачів

## 1. Мета та огляд
Відповідно до пункту 68 `docs/changes/MainChange.md`:
- **Наглядачі** (`process = 'Наглядач'`) **НЕ** отримують повідомлення про зміну навчальних матеріалів.
- **Територіали** (`process = 'Територіал'`) **отримують** повідомлення про зміну навчальних матеріалів відповідно до свого напрямку (ТЗ або ВВ).
- **Керівники магазинів** (`process IN ('Керівник', 'Керівник Стажер')`) та **Працівники/Стажери** відповідної посади продовжують отримувати сповіщення, як і раніше.

---

## 2. Детальні вимоги та логіка

### 2.1. Виключення Наглядачів
- У `database/material_notifications.py` під час формування списку отримувачів (`create_recipients_for_event`):
  - З `managers.db` вибираються ID всіх активних наглядачів (`process = 'Наглядач'`).
  - Вони додаються до набору `excluded_user_ids`.
  - Жоден користувач із цим ID (навіть якщо він присутній у `users.db`) не може бути доданий до списку отримувачів сповіщення про зміну навчальних матеріалів.

### 2.2. Включення Територіалів за напрямком (ТЗ / ВВ)
- Визначається напрямок посади, для якої оновлено матеріал:
  ```python
  pos_direction = await get_position_direction(role)  # Повертає 'ТЗ' або 'ВВ'
  ```
- З `managers.db` вибираються активні територіали:
  - `process = 'Територіал'` та `(status IS NULL OR status != 'fired')`
  - Фільтрація за напрямком:
    - Якщо `pos_direction == 'ТЗ'`: вибираються територіали, де `territorial_type = 'ТЗ'` або `territorial_type IS NULL` чи `territorial_type = ''`.
    - Якщо `pos_direction == 'ВВ'`: вибираються територіали, де `territorial_type = 'ВВ'` або `territorial_type IS NULL` чи `territorial_type = ''`.
- Додаються до списку `recipients_data` з:
  - `role_type`: `'територіал'`
  - `shop`: `'Всі магазини напрямку'` або `'Не вказано'`
  - `city`: `row['city']` або `'Не вказано'`
- Дедуплікація здійснюється через `seen_user_ids`.
- Розбиття на батчі (хвилі) по 40 осіб зберігається.

### 2.3. Аналітика ознайомлення (`bot/menus/developer.py`)
- У меню аналітики ознайомлення (`dev_an_ack_menu`) додається кнопка:
  - `🗺 Територіали` (`callback_data="dev_ack_cat:територіал"`)
- У словник `cat_titles` додається:
  - `"територіал": "🗺 Територіали"`
- Запит аналітики `get_event_analytics_for_category(event_id, "територіал")` вже використовує `LOWER(role_type)`, тому агрегація та формування списку ознайомлених/неознайомлених для територіалів працюватиме без додаткових модифікацій БД.

## 3. План тестування (Verification)
Створюється тестовий скрипт `scratch/test_observer_and_territorial_notifications.py`, який перевіряє:
1. Оновлення матеріалу для посади напрямку **ТЗ**:
   - Працівник посади отримує сповіщення.
   - Керівник магазину отримує сповіщення.
   - Територіал напрямку **ТЗ** отримує сповіщення.
   - Територіал напрямку **ВВ** **НЕ** отримує сповіщення.
   - Наглядач **НЕ** отримує сповіщення.
2. Оновлення матеріалу для посади напрямку **ВВ**:
   - Територіал напрямку **ВВ** отримує сповіщення.
   - Територіал напрямку **ТЗ** **НЕ** отримує сповіщення.
   - Наглядач **НЕ** отримує сповіщення.
3. Фіксація ознайомлення територіала (`mark_recipient_acknowledged`) та розрахунок статистики для категорії `'територіал'`.
