# Design Document: Динамічна камера та Ken Burns ефекти для Серії 04 у CapCut

**Дата:** 2026-11-11  
**Проєкт:** "Richard Still Alive" (Річард ще живий), Серія 04 (`04_Friction_Fire`)  
**Ціль:** Програмне додавання плавних рухів камери (Ken Burns: Zoom In, Zoom Out, Slow Pan) у проєкт CapCut для підвищення динаміки та утримання уваги глядача.

---

## 1. Контекст та мета

Наразі всі 200 кадрів серії 04 виставлені на таймлайні проєкту CapCut `1111` як статичні зображення, синхронізовані з голосом диктора. Щоб перетворити статичну слайд-шоу структуру на кінематографічний відеоряд у стилі якісного YouTube-наукпопу (Vox, Kurzgesagt, National Geographic), необхідно додати динаміку камери.

Замість випадкових або одноманітних зумів використовується **розумна адаптивна динаміка**, яка враховує категорію кожного кадру з розкадровки [02_storyboard_shots.md](file:///Users/daniildusinskij/All/YouTube/Richard%20still%20alive/04_Friction_Fire/Text/02_storyboard_shots.md).

## 2. Архітектура розподілу рухів за типами кадрів

### 2.1. `Hybrid` (84 кадри: Річард у реальному середовищі острова)
- **Призначення:** Занурення у виживання, атмосфера самотності на острові.
- **Розподіл:**
  - 60% кадрів: **Slow Zoom In** (плавний наїзд камери від `1.00` до `1.07` через `UNIFORM_SCALE`).
  - 40% кадрів: **Slow Pan** (горизонтальний політ камери від `position_x: -0.025` до `+0.025` або навпаки, з базовим збільшенням `1.05`, щоб не оголювати чорні краї кадру).

### 2.2. `Diagram` (28 кадрів: інженерні схеми, фізика тертя, інфографіка)
- **Призначення:** Легкість сприйняття складної інформації без візуального шуму.
- **Динаміка:** **Micro Zoom In** від `1.00` до `1.03` (ледве помітний рух, що оживляє схему, але не заважає зчитувати текст, стрілки та показники температури). Для коротких кадрів (< 3.2 с) зберігається статика `1.00`.

### 2.3. `2D Comic` (38 кадрів: внутрішні органи, гіпоталамус, калорії, гумор)
- **Призначення:** Емоційний акцент та розважальна динаміка.
- **Динаміка:** **Punchy Zoom In** від `1.00` до `1.09` - `1.10`. Камера фокусується на емоції персонажа або ключовій дії в коміксі.

### 2.4. `Diptych 2D` та `Triptych 2D` (50 кадрів: спліт-скріни, міф проти реальності, етапи)
- **Призначення:** Порівняння концепцій (кіно проти фізіології).
- **Динаміка:** **Left-to-Right Pan**. Базовий масштаб виставляється на `1.04`, а горизонтальна координата плавно зміщується від `position_x: -0.02` до `+0.02`. Це веде погляд глядача від лівої панелі (міф) до правої панелі (наукова реальність) синхронно з текстом диктора.

## 3. Технічна структура даних CapCut (`draft_info.json`)

Внутрішня архітектура CapCut підтримує список властивостей анімації всередині об'єкта `segment` у полі `common_keyframes`:

```json
{
  "id": "<Segment_UUID>",
  "common_keyframes": [
    {
      "id": "<KeyframeList_UUID_1>",
      "property_type": "UNIFORM_SCALE",
      "material_id": "",
      "keyframe_list": [
        {
          "id": "<KF_UUID_1>",
          "curveType": "Line",
          "graphID": "",
          "left_control": {"x": 0.0, "y": 0.0},
          "right_control": {"x": 0.0, "y": 0.0},
          "time_offset": 0,
          "values": [1.0]
        },
        {
          "id": "<KF_UUID_2>",
          "curveType": "Line",
          "graphID": "",
          "left_control": {"x": 0.0, "y": 0.0},
          "right_control": {"x": 0.0, "y": 0.0},
          "time_offset": 4500000,
          "values": [1.07]
        }
      ]
    }
  ]
}
```

### Правила генерації параметрів:
1. **Часові мітки:** Перший ключ завжди встановлюється на `time_offset: 0` (початок сегмента). Другий ключ завжди встановлюється на `time_offset: segment_duration_us` (кінець сегмента).
2. **Захист від чорних смуг (Safe Framing):** Будь-який рух панорамування (`KFTypePositionX`) супроводжується базовим `UNIFORM_SCALE >= 1.04`, щоб рамка зображення не зміщувалася за межі полотна 16:9.
3. **Плавність (Interpolation):** Використовується лінійна інтерполяція `"Line"`, яка гарантує стабільний плавний рух без ривків на стиках сегментів.

## 4. План виконання та верифікації

1. **Створення бекапу:** Збереження поточної робочої копії проєкту в `/tmp/capcut_backup_1111_pre_effects`.
2. **Парсинг категорій розкадровки:** Зчитування форматів кожного з 200 кадрів з файлу `02_storyboard_shots.md`.
3. **Генерація ключових кадрів:** Скрипт генерує унікальні UUID та додає `common_keyframes` до кожного відеосегмента.
4. **Оновлення всіх копій файлів проєкту:** Одночасний запис у `draft_info.json`, `draft_info.json.bak`, `template-2.tmp` (кореневий та у папці `Timelines/*`).
5. **Тестування валідності JSON:** Перевірка цілісності структури JSON та коректності зчитування CapCut.
