# Дизайн: Додавання ролі «Територіал» до аудиторії новин

## 1. Мета та опис завдання
У боті «Bulka Edu» на кроці вибору аудиторії для корпоративних новин («👥 Створення новини - Крок 3/4: Аудиторія (Ролі)») необхідно додати можливість вибору ролі **«Територіал»**.
При виборі цієї ролі активні територіальні керуючі мережі мають отримувати новину відповідно до обраного фільтра міст.
Розділ опитувань («📊 Опитування») залишається без змін за рішенням замовника.

---

## 2. Архітектура та компоненти

### 2.1. Інтерфейс вибору ролей для новини (FSM & Keyboards)
- **Файл:** `bot/menus/developer.py`
- **Функція:** `_show_news_roles_selection(callback: CallbackQuery, state: FSMContext)`
- **Зміни:**
  - Список доступних ролей для новин розширюється:
    `all_roles = ["Працівник", "Стажер", "Керівник", "Територіал", "Наглядач"]`
  - Кнопка для ролі «Територіал» генерується автоматично:
    `callback_data="dev_news_toggle_role:Територіал"`
  - Інлайн-клавіатура відображає поточний стан (позначка `✅ ` або `⬜️ `) для кожної ролі.
  - Зберігається валідація у `dev_news_toggle_role_handler`: користувач не може зняти всі позначки (щонайменше 1 роль має бути обрана).

### 2.2. Попередній перегляд новини
- **Файл:** `bot/menus/developer.py`
- **Функція:** `_show_news_preview(callback: CallbackQuery, state: FSMContext)`
- **Зміни:**
  - У тексті попереднього перегляду в полі ролей відображатиметься «Територіал» (наприклад: `Працівник, Стажер, Територіал`).
  - Лічильник `recipients = await get_matching_news_recipients(selected_roles, selected_city)` повертає точну кількість адресатів з урахуванням територіалів.

### 2.3. Вибірка отримувачів у базі даних
- **Файл:** `database/surveys.py` (використовується `get_matching_news_recipients` з `database/news.py`)
- **Функція:** `get_matching_survey_recipients(target_roles, target_city, db_path)`
- **Зміни:**
  - Додається блок обробки `if "Територіал" in target_roles:`:
    1. Пошук у `MANAGERS_DB_PATH` (`managers.db`):
       ```sql
       SELECT uid FROM managers
       WHERE process = 'Територіал'
         AND (status = 'active' OR status IS NULL)
       ```
       Якщо задано конкретне місто (`city_filter`):
       ```sql
       AND city = ?
       ```
    2. Пошук у `DB_PATH` (`users.db`):
       ```sql
       SELECT user_id FROM users
       WHERE role = 'Територіал'
       ```
       Якщо задано конкретне місто (`city_filter`):
       ```sql
       AND city = ?
       ```
    3. Додавання отриманих ID до набору отримувачів `matched_uids`.
  - Звільнені територіали (`status = 'fired'`) автоматично відфільтровуються на рівні `get_matching_news_recipients`.

---

## 3. Обробка граничних випадків та помилок
1. **Обрано конкретне місто:**
   - Новина надходить тільки тим територіалам, чиє місто у `managers.db` співпадає з обраним.
2. **Обрано «🌐 Усі міста»:**
   - Новина надходить усім активним територіалам незалежно від міста.
3. **Звільнений територіал:**
   - Якщо у записі стоїть `status = 'fired'`, такий користувач не отримує новину.
4. **Опитування:**
   - У розділі опитувань константа `ALL_SURVEY_ROLES` не змінюється, опитування не пропонують роль «Територіал».
