# Дизайн-специфікація: Доступ Територіального керівника до «Нагадати тему» та перегляд навчання (Read-Only)

## 1. Мета та контекст
Територіальний керівник (`process = 'Територіал'` у `managers.db`) координує роботу торгових точок або напрямків власного виробництва. Для якісного супроводу стажерів та перевірки стандартів територіал повинен:
1. Мати повноцінний доступ до функціоналу швидкого пошуку знань **«🧠 Нагадати тему»** (`remind_topic_global` та `remind_topic_for_intern`).
2. Мати можливість вільно переглядати навчальні матеріали до всіх посад у системі (тексти, відео, тести, фото) у меню **«📚 Навчальні матеріали»**.
3. Бути обмеженим суворим режимом **тільки перегляд (Read-Only)**: будь-які кнопки створення, редагування, заміни контенту чи видалення тестів/матеріалів повинні бути приховані на рівні інтерфейсу та заблоковані на рівні серверних хендлерів.

---

## 2. Архітектурні зміни та права доступу

### 2.1. Допоміжні функції доступу (`bot/menus/developer.py`)
- Оновити `_ensure_developer(callback: CallbackQuery, require_main: bool = False, allow_observer: bool = False, allow_territorial: bool = False) -> bool`:
  - Додати прапорець `allow_territorial: bool = False`.
  - Якщо `allow_territorial and not is_dev`:
    - Перевірити `if await is_territorial_user(user_id): return True`.
- Усі хендлери мутацій (редагування/видалення/додавання матеріалів, запитань, медіа) викликають `_ensure_developer(callback, allow_territorial=False)`.

### 2.2. Хендлер «🧠 Нагадати тему» (`bot/handlers.py`)
- У `remind_topic_global_callback`:
  - Додати перевірку `is_terr = await is_territorial_user(user_id)`.
  - Оновити перевірку доступу:
    ```python
    if not (is_hr or is_dev or is_obs or is_mgr or is_terr):
        await callback.answer("Ця функція доступна лише для керівництва.", show_alert=True)
        return
    ```
  - Оновити визначення кнопки повернення:
    - Якщо `is_terr`, повертатися до `dev_main_study`.
- У `remind_topic_for_intern_callback`:
  - Переконатися, що `is_territorial_user` проходить перевірку прав для запуску нагадування теми по конкретному стажеру.

## 3. Логіка перегляду навчальних матеріалів (Read-Only)

### 3.1. Вибір посади та днів
- У хендлерах `developer_materials_menu`, `developer_videos_menu`, `developer_tests_menu`, `developer_photos_menu`:
  - Дозволити вхід територіалам через `allow_territorial=True`.
  - Відображати всі доступні посади (`AVAILABLE_ROLES` / з `positions.db`), як підтвердив користувач.

### 3.2. Відключення кнопок редагування (UI Read-Only)
- При побудові інлайн-клавіатур перегляду матеріалів визначати:
  ```python
  is_readonly = await is_observer_user(user_id) or await is_territorial_user(user_id)
  ```
- Для матеріалів (`dev_mat_type|text`):
  - Приховувати кнопки «✏️ Редагувати», «🗑 Видалити», «➕ Додати блок».
  - Залишати навігацію по блоках та кнопку «⬅️ Назад».
- Для відео (`dev_videos_menu`):
  - Приховувати кнопки «Замінити відео» / «Видалити відео».
- Для тестів (`dev_tests_menu`):
  - Приховувати кнопки «➕ Додати питання», «✏️ Редагувати», «🗑 Видалити тест».
  - Відображати список запитань та відповідей лише для ознайомлення.
- Для фото (`dev_photos_menu`):
  - Приховувати кнопки завантаження / заміни фото.
