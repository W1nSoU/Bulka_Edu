# Специфікація: Додавання Керівників та Територіалів через 24-годинні інвайт-посилання та авто-переведення підлеглих

**Дата:** 2026-09-03  
**Статус:** Схвалено до реалізації  
**Ціль:** Повна відмова від ручного введення Telegram ID при додаванні Керівників та Територіалів. Реалізація покрокового майстра створення 24-годинних інвайт-посилань формату `https://t.me/<Bot>?start=<creator_id>-<token>` з попереднім налаштуванням міста, магазинів/типу та автоматичним переведенням підлеглих (стажерів, працівників, керівників) після завершення реєстрації.

---

## 1. Архітектура та права доступу

### 1.1. Матриця прав доступу
1. **Будь-який Адміністратор (роль Developer / Адміністратор)**:
   - Створення інвайт-посилань для:
     - **Стажерів** (будь-яке місто, будь-яка посада).
     - **Керівників** (будь-яке місто, вибір до 5 магазинів, закріплення за територіалом міста або пряме підпорядкування адміну).
     - **Територіалів** (будь-яке місто, вибір типу `ТЗ` або `ВВ`, вибір перенесення керівників міста).
     - **Наглядачів** (глобальний доступ до аналітики/навчання).
2. **Територіальний керівник (роль Територіал)**:
   - Створення інвайт-посилань **виключно для**:
     - **Стажерів** свого міста та свого напрямку (`ТЗ` або `ВВ`).
     - **Керівників** свого міста (до 5 магазинів міста, новий керівник автоматично отримує `responsible_uid = territorial_uid`).
   - ⛔ **Заборонено**: Створення або перегляд інших територіалів, наглядачів, адміністраторів. Меню «Територіали» для них приховано.

---

## 2. Схема бази даних токенів (`tokens.db`)

Таблиця `tokens` у `database/tokens.py` розширюється (із безпечною авто-міграцією в `init_tokens_db`):
- `extra_data TEXT DEFAULT NULL` — JSON-рядок з додатковими параметрами:
  - Для керівників: `{"shops": ["Магазин 1", ...], "transfer_on_reg": 1, "responsible_uid": 123456}`.
  - Для територіалів: `{"territorial_type": "ТЗ", "transfer_on_reg": 1}`.
- `transfer_on_reg INTEGER DEFAULT 0` — індикатор того, що при активації токена потрібно виконати переприв'язку співробітників.

## 3. Майстер генерації посилання для Керівника

### 3.1. Кроки майстра (`dev_add_manager`):
1. **Місто**:
   - Для **Територіала**: встановлюється його місто автоматично.
   - Для **Адміністратора**: інлайн-вибір з усіх активних міст.
2. **Магазини (мульти-вибір до 5)**:
   - Інлайн-кнопки перемикання магазинів обраного міста: `[ ] Магазин` / `[✅] Магазин`.
   - Кнопка `Готово` (доступна, якщо обрано хоча б 1 магазин або якщо в місті немає магазинів).
3. **Запит на переведення співробітників магазинів**:
   - Бот перевіряє кількість людей у цих магазинах:
     `count_users_in_shops(city, selected_shops)`
   - Якщо знайдено > 0:
     > «👥 У цих магазинах знайдено **{interns}** стажерів та **{workers}** працівників (закріплені за Територіалом/Адміністратором).
     > Перевести їх під керівництво цього керівника після його реєстрації?»
     > **[ ✅ Так, перевести ]** / **[ ❌ Ні, залишити як є ]**
   - Якщо 0 — крок автоматично завершується зі значенням `transfer_on_reg = 0`.
4. **Формування посилання**:
   - Зберігається токен у `tokens.db` з часом дії 24 години.
   - Видається повідомлення:
     > «🔗 **Посилання для запрошення Керівника створено!**
     > 🏙️ Місто: ...
     > 🏪 Магазини: ...
     > 👥 Авто-переведення співробітників: Так/Ні
     > ⏱️ Дійсне 24 години
     > <code>https://t.me/<Bot>?start=<creator_id>-<token></code>»

### 3.2. Реєстрація нового керівника:
1. Кандидат переходить за лінком і вводить ПІБ.
2. Бот створює:
   - Запис у `users`: роль «Керівник», статус «Стажер».
   - Запис у `managers`: процес «Керівник Стажер», місто, перелік магазинів, `responsible_uid`.
   - Викликає `use_token(token, user_id)`.
3. Якщо `transfer_on_reg == 1`:
   - Викликається `transfer_users_by_shops(city, shops, new_manager_uid)`.
   - Творцю посилання (Територіалу чи Адміну) надсилається приватне повідомлення:
     > «👔 Керівник **{ПІБ}** успішно зареєструвався за вашим посиланням!
     > 🏪 Магазини: {shops_list}
     > ✅ Під його керівництво переведено {count} співробітників.»
4. Новому керівнику відкривається навчання керівника (`📚 Навчання`).

## 4. Майстер генерації посилання для Територіала

### 4.1. Кроки майстра (`dev_territorial_add`):
Доступно будь-якому Адміністратору.
1. **Місто**:
   - Інлайн-вибір міста з бази.
2. **Тип Територіала**:
   - `Торговий Зал (ТЗ)`
   - `Власне Виробництво (ВВ)`
   - Якщо в місті вже є такий тип, виводиться мітка `(вже існує ⚠️)`.
3. **Запит на перенесення керівників міста**:
   > «Перенести **всіх керівників** міста **{місто}** під управління цього Територіала ({тип}) після його реєстрації?»
   > **[ ✅ Так, перенести ]** / **[ ❌ Ні, залишити як є ]**
4. **Формування посилання**:
   - Зберігається токен у `tokens.db` з часом дії 24 години.
   - Видається deep-link:
     `https://t.me/<Bot>?start=<creator_id>-<token>`.

### 4.2. Реєстрація нового територіала:
1. Кандидат переходить за лінком і вводить ПІБ.
2. Бот створює:
   - Запис у `users`: роль «Територіал».
   - Запис у `managers`: процес «Територіал», місто, `territorial_type`.
   - Позначає токен використаним (`use_token`).
3. Якщо було обрано перенесення:
   - Викликається `reassign_city_managers_to_territorial(city, new_territorial_uid)`.
   - Усі діючі керівники міста отримують `responsible_uid = new_territorial_uid`.
4. Творцю посилання (Адміністратору) надсилається звіт про успішну реєстрацію та кількість перепідпорядкованих керівників міста.

---

## 5. Граничні випадки та безпека

1. **Термін дії**: Після 24 годин спроба реєстрації повертає інформаційне повідомлення про прострочене посилання.
2. **Одноразовість**: Використаний токен блокує повторні спроби реєстрації.
3. **Обробка помилок Telegram**: Надсилання сповіщень творцям посилань обгорнуто в `try/except (TelegramBadRequest, TelegramForbiddenError)`, що гарантує відсутність збоїв і падінь бота.
4. **Видалення старого введення ID**: Повністю усунено застарілі FSM стани введення числових ID вручну для цих ролей.
