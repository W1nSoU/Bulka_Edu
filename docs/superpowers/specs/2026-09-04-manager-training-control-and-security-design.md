# Дизайн-документ: Контроль навчання, статус «Керівник Стажер», права територіалів та безпека ролей

## 1. Огляд та цілі

Цей документ фіксує узгоджені рішення для:
1. Усунення можливості створення інвайт-посилань на посаду «Керівник» керівниками магазинів та керівниками-стажерами.
2. Додавання функції звільнення працівника безпосередньо з картки працівника в меню Керівника (з обов'язковим підтвердженням).
3. Обмеження прав зміни тривалості навчального курсу (кількості днів) посади «Керівник» виключно для ролі «Адміністратор».
4. Надання Територіальним керівникам доступу до «📚 Навчальні матеріали» у режимі лише для перегляду (Read-Only).
5. Відображення навчального поступу для ролі «Керівник Стажер» у списку та картці керівників (бейджі, статистика, кнопка «📅 Навчальні дні») як для Територіалів, так і для Адміністраторів.
6. Впровадження списків стажерів та працівників «Без керівника» в меню управління персоналом (`dev_users_menu`) для Територіалів та Адміністраторів.

## 2. Архітектура та зміни компонентів

### 2.1. Меню Керівника: Безпека токенів та звільнення працівника (`bot/menus/manager.py`)

#### А. Фільтрація ролей при генерації токенів:
- У функціях `manager_process_add_city_callback` та `manager_process_add_shop_callback`:
  - Замінити пряме використання `AVAILABLE_ROLES` на фільтрований список:
    ```python
    filtered_roles = [r for r in AVAILABLE_ROLES if r not in ("Керівник", "Керівник Стажер")]
    ```
  - Керівники магазинів та керівники-стажери можуть запрошувати лише лінійний персонал магазину.

#### Б. Кнопка «Звільнити» в картці співробітника:
- У функції `_show_intern_details(event, intern_id, back_callback)`:
  - Додати кнопку `[ ❌ Звільнити ]` (callback: `mgr_fire_prompt:{intern_id}:{ret_code}`).
- Створити обробник `manager_fire_prompt_handler(callback)`:
  - Відображає текст попередження:
    `⚠️ Ви дійсно бажаєте звільнити працівника <b>{full_name}</b>?\n\nЦю дію неможливо скасувати.`
  - Клавіатура:
    - `[ ✅ Так, звільнити ]` (`mgr_fire_confirm:{intern_id}:{ret_code}`)
    - `[ ⬅️ Скасувати ]` (`mgr_view_intern_{intern_id}:{ret_code}`)
- Створити обробник `manager_fire_confirm_handler(callback)`:
  - Викликає `delete_user(intern_id)`.
  - Логує подію через `log_training_event(event_type="fired", ...)`.
  - Повідомляє керівника про успішне звільнення та надає кнопку повернення до списку команди `mgr_my_team`.

### 2.2. Налаштування кількості днів ролі «Керівник» (`bot/menus/developer.py`)
- У функції `dev_pos_edit_days_start`:
  - Перевірити доступ: лише користувачі, для яких `await is_developer_user(user_id)` повертає `True`, мають право змінювати дні.
  - Якщо посада — `Керівник` (`pos['name'] == 'Керівник'`), додатково гарантувати, що Територіали чи Наглядачі не можуть ініціювати зміну днів (повертати alert: `⛔️ Змінювати тривалість курсу Керівника може лише Адміністратор.`).
- У функції `dev_pos_edit_days_process`:
  - Повторно перевірити `is_developer_user(message.from_user.id)`.

### 2.3. Меню Територіала: «📚 Навчальні матеріали» (Read-Only) (`bot/menus/developer.py`)
- У `_admin_cho_keyboard`:
  - Кнопку `[ 📚 Навчальні матеріали ]` (`dev_main_study`) показувати для:
    `if is_admin or is_observer or is_territorial:`
- У `dev_main_study_handler`:
  - Дозволити вхід Територіалам (`is_territorial`).
- У `_admin_study_keyboard`:
  - Кнопку `📚 Змінити змісти` приховувати, якщо `is_observer or is_territorial`.
- Усі хендлери редагування навчальних матеріалів/тестів/відео/фото залишаються захищеними перевіркою `is_admin` (якщо Територіал спробує викликати колбек редагування — отримує `⛔️ Доступ заборонено`).

### 2.4. Відображення «Керівника-стажера» в «Команді керівників» (`bot/menus/developer.py`)

#### А. Список керівників (`_build_managers_team_view`):
- Для кожного керівника у списку перевіряється поле `process`.
- Якщо `process == 'Керівник Стажер'`:
  - Отримуються дані користувача з таблиці `users` (`user_id = hr['uid']`).
  - Отримується загальна кількість днів для ролі «Керівник» (`total_days = await get_days_count_for_role('Керівник')`).
  - Поточний день навчання: `cur_day = u.get('current_block', 1)`.
  - Текст кнопки:
    `👔 {name} | 🎓 Стажер (День {cur_day}/{total_days}) | {abbr}`.
- Для звичайних керівників формат залишається стандартним:
  `👔 {name} | {username} | {abbr}`.

#### Б. Картка керівника (`_build_manager_card`):
- Якщо `mgr.get('process') == 'Керівник Стажер'`:
  - Отримати прогрес навчання користувача через `get_user_progress(manager_uid)`.
  - Додати блок інформації:
    ```
    🎓 <b>Статус:</b> Керівник Стажер (навчання)
    📅 <b>День навчання:</b> {cur_day} з {total_days}
    📊 <b>Пройдено тестів:</b> {completed_days} / {total_days}
    ```
  - Додати кнопку:
    `[ 📅 Навчальні дні ]` (callback: `dev_days_manage:{manager_uid}:mgr_team`).
- У хендлері повернення `_decode_back_callback`:
  - Додати підтримку коду `mgr_team` ➡️ повернення до `dev_mgr_view:{user_id}`.

### 2.5. Стажери та працівники «Без керівника» (`bot/menus/developer.py`, `database/users.py`)

#### А. Критерій «Без керівника»:
Користувач вважається таким, що не має керівника магазину, якщо:
1. Його `manager_id IS NULL`;
2. АБО його `manager_id` є ID одного з Територіалів (`is_territorial_user(manager_id) == True`);
3. АБО магазин, за яким закріплений співробітник, не має активного призначеного керівника в таблиці `managers` (`get_manager_by_shop(city, shop)` повертає `None` або керівника зі статусом `fired`).

#### Б. Інтерфейс у `_users_staff_keyboard`:
- Додати дві кнопки:
  - `[ 🎓 Стажери без керівника ]` (`dev_users_interns_no_mgr`)
  - `[ 👷 Працівники без керівника ]` (`dev_users_workers_no_mgr`)
- Обробники:
  - `developer_list_interns_no_manager(callback, page=0)`:
    - Отримує стажерів (`get_all_interns()`).
    - Якщо Територіал — фільтрує за містом/магазинами Територіала.
    - Фільтрує тих, хто підпадає під критерій «без керівника магазину».
    - Відображає пагінований список аналогічно до `_developer_show_users_list`.
  - `developer_list_workers_no_manager(callback, page=0)`:
    - Отримує працівників (`get_all_workers()`).
    - Якщо Територіал — фільтрує за містом/магазинами Територіала.
    - Фільтрує тих, хто підпадає під критерій «без керівника магазину».
    - Відображає пагінований список.

## 3. План верифікації та валідації
1. **Тест ізоляції ролей при створенні інвайтів:**
   - Перевірити, що `manager_process_add_city_callback` та `manager_process_add_shop_callback` не містять `"Керівник"` та `"Керівник Стажер"`.
2. **Тест кнопки звільнення:**
   - Перевірити виклик `mgr_fire_prompt`, появу підтвердження та виконання `mgr_fire_confirm`.
3. **Тест прав на зміну днів:**
   - Перевірити, що Територіал та Наглядач не можуть змінити дні для ролі `Керівник`.
4. **Тест режиму Read-Only для Територіала:**
   - Перевірити доступ до `dev_main_study`, перегляд списку матеріалів та відсутність кнопок редагування змістів.
5. **Тест відображення керівника-стажера:**
   - Перевірити генерацію бейджа в списку керівників та наявність кнопки `[ 📅 Навчальні дні ]` в картці.
6. **Тест фільтрації «Без керівника»:**
   - Перевірити відображення користувачів, закріплених за магазинами без активного керівника або тимчасово прив'язаних до Територіала.
