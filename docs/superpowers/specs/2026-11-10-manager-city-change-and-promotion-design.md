# Дизайн-документ: Зміна міста для керівників та кнопка «Переведення на Керівника»

**Дата створення:** 2026-11-10  
**Статус:** На затвердженні користувачем  
**Проект:** Bulka Education (`Bulka_Edu`)  

---

## 1. Мета та контекст

В адміністративній панелі керування керівниками (`dev_manage_managers`) виявлено дві потреби:
1. **Зміна міста для керівника:** У картках керівників наразі немає можливості змінити місто після створення. Якщо у керівника вказано місто без торгових точок (наприклад, підрозділ «РЦ»), екран редагування магазинів виявляється порожнім без можливості обрати дійсні магазини. Необхідно надати адміністратору зручний інтерфейс зміни міста з автоматичним безпечним відкріпленням старих магазинів та миттєвим переходом до вибору нових.
2. **Переведення на Керівника:** Керівники-стажери (`process == 'Керівник Стажер'`) після проходження внутрішнього навчання повинні переводитися в статус повноцінного керівника (`process == 'Керівник'`). Потрібна зручна кнопка в картці керівника для адміністратора/територіала, яка в один клік (із підтвердженням) змінює статус у системі, закриває навчальні дні стажера та сповіщає співробітника.

## 2. Архітектура та компоненти

### 2.1. База даних (`database/managers.py`)

1. **`update_manager_city(uid: int, new_city: str) -> bool`**:
   - Отримує поточні дані керівника через `get_manager_by_uid(uid)`.
   - Якщо `new_city == old_city`, повертає `True` без змін.
   - Якщо у керівника були закріплені магазини в `old_city`, викликає функцію `reassign_removed_shops_users_to_territorial(old_city, old_shops, uid)`:
     - Усі стажери та працівники відкріплених магазинів передаються відповідному Територіалу старого міста (нуль втрачених підлеглих).
   - Оновлює таблицю `managers`:
     ```sql
     UPDATE managers SET city = ?, shops = '[]' WHERE uid = ?
     ```
   - Синхронно оновлює таблицю `users` у `users.db`:
     ```sql
     UPDATE users SET city = ? WHERE user_id = ?
     ```
   - Повертає `True`.

2. **`promote_manager_trainee(uid: int) -> bool`**:
   - Оновлює таблицю `managers`:
     ```sql
     UPDATE managers SET process = 'Керівник' WHERE uid = ? AND process = 'Керівник Стажер'
     ```
   - Оновлює таблицю `users`:
     ```sql
     UPDATE users SET status = 'Працівник' WHERE user_id = ?
     ```
   - Повертає `True`.

### 2.2. Інтерфейс бота (`bot/menus/developer.py`)

#### А. Кнопка «🎓 Перевести на Керівника» в картці (`dev_mgr_view`)
1. **Умова показу кнопки:**
   - `mgr.get("process") == "Керівник Стажер"` та `mgr.get("status") != "fired"` та користувач має права адміна/територіала.
2. **Розміщення:**
   - У блоці дій картки додається кнопка:
     `[🎓 Перевести на Керівника] -> callback_data="dev_mgr_promote_ask:{uid}"`.
3. **Екран підтвердження (`dev_mgr_promote_ask`):**
   - Текст повідомлення:
     > 🎓 **Підтвердження переведення на Керівника**
     >
     > Ви дійсно бажаєте перевести співробітника **{full_name}** у статус повноцінного Керівника?
     > • Навчальні дні стажера будуть офіційно завершені.
     > • Статус у системі зміниться на «Керівник».
     > • Співробітник отримає сповіщення про успішне завершення стажування.
   - Кнопки:
     `[✅ Так, перевести] -> dev_mgr_promote_confirm:{uid}`
     `[⬅️ Скасувати] -> dev_mgr_view:{uid}`
4. **Обробник підтвердження (`dev_mgr_promote_confirm`):**
   - Перевіряє актуальний статус у базі (захист від подвійного кліку).
   - Викликає `promote_manager_trainee(uid)`.
   - Надсилає вітальне сповіщення в особисті керівнику через `bot.send_message`:
     > 🎉 **Вітаємо!**
     >
     > Ваше навчання та стажування на посаду Керівника успішно завершено!
     > Вам надано повний доступ до функціоналу Керівника в системі Bulka Education.
   - Якщо користувач заблокував бота, виняток `TelegramForbiddenError` перехоплюється м'яко без збоїв.
   - Оновлює картку керівника (`dev_mgr_view`), де кнопки «Навчальні дні» та «Перевести на Керівника» вже відсутні.

#### Б. Кнопка «🏙️ Змінити місто» в підменю редагування (`dev_mgr_edit_menu`)
1. **Розміщення:**
   - У `dev_mgr_edit_menu` клавіатура набуває структури:
     `[🏪 Змінити магазин]  [🏙️ Змінити місто]`
     `[👤 Змінити ПІБ]      [🚫 Звільнити]`
     `[⬅️ Назад до картки]`
   - Callback для кнопки міста: `dev_mgr_ch_city:{manager_uid}`.
2. **Екран вибору нового міста (`dev_mgr_change_city_start`):**
   - Отримує список активних міст через `_get_active_city_names()`.
   - Будує інлайн-список міст:
     - Кнопка для кожного міста: `dev_mgr_city_set:{manager_uid}:{city_idx}`.
     - Якщо місто збігається з поточним: позначається як `🏙️ {city} (поточне)`.
     - Кнопка повернення: `[⬅️ Скасувати] -> dev_mgr_edit_menu:{manager_uid}`.
3. **Обробник вибору нового міста (`dev_mgr_process_city_set`):**
   - Якщо обрано поточне місто:
     - Видає alert: *«Керівник вже закріплений за цим містом.»*.
   - Якщо обрано інше місто:
     - Викликає `update_manager_city(manager_uid, new_city)`.
     - Зберігає в стан FSM `DeveloperStates.waiting_edit_manager_shops`:
       `edit_mgr_uid=manager_uid`, `manager_city=new_city`, `selected_shops=[]`, `original_shops=[]`.
     - Одразу викликає та відображає клавіатуру вибору магазинів для нового міста:
       `_build_edit_shops_keyboard(new_city, [], manager_uid)`.
     - Якщо в обраному місті ще немає жодного магазину (`len(shops_in_city) == 0`):
       - Відображається підказка:
         *«🏪 Зміна магазинів для керівника {full_name} (місто {new_city}):\n\n⚠️ У цьому місті ще немає доданих магазинів. Ви можете додати їх у меню «Керування магазинами» або завершити налаштування без привʼязки точок.»*
         з активною кнопкою `[✅ Готово]` та `[⬅️ Скасувати]`.

## 3. Безпека даних та цілісність підлеглих

1. **Захист від втрати підлеглих:**
   При зміні міста керівника всі стажери та співробітники його колишніх магазинів не залишаються без нагляду. Виклик `reassign_removed_shops_users_to_territorial` перевіряє прив'язку кожного магазину та передає команду відповідному Територіалу старого міста.
2. **Консистентність між базами:**
   Поле `city` обов'язково оновлюється одночасно в таблиці `managers` (`managers.db`) та в таблиці `users` (`users.db`).
3. **Права доступу:**
   До обох операцій мають доступ виключно адміністратори та відповідальні територіали через стандартну перевірку `_check_access`.

Файл тестів: `tests/test_manager_city_and_promotion.py`.
1. **Тест оновлення міста (`test_update_manager_city`):**

   - Зміна міста на місто Б.
   - Перевірка, що в `managers` місто змінилося на Б, а `shops` став порожнім `[]`.
   - Перевірка оновлення міста в таблиці `users`.
2. **Тест підвищення стажера (`test_promote_manager_trainee`):**
   - Створення керівника зі статусом `Керівник Стажер` та користувача зі статусом `Стажер`.
   - Виклик `promote_manager_trainee`.
   - Перевірка, що `process == 'Керівник'`, а статус користувача `Працівник`.
3. **Тест інтерфейсу клавіатур:**
   - Перевірка генерації кнопки `🎓 Перевести на Керівника` для стажера.
   - Перевірка відсутності кнопки переведення для звичайного керівника.
   - Перевірка наявності кнопки `🏙️ Змінити місто` в `dev_mgr_edit_menu`.
