# Технічне завдання: Master Key та серверна перевірка для Bulka Edu

**Мета:** Забезпечити захист від несанкціонованого використання бота, контролювати активацію та моніторити запуск на сторонніх серверах.

**Роль `security.md`:** 
- Використовується як To-Do та журнал виконання для кожного етапу розробки захисту.
- Всі реалізовані пункти та поточний статус записуються там для контролю.

---

## 1. Основні принципи захисту

### 1.1 Master Key
- Генерується та зберігається на твоєму сервері розробника.  
- Має довжину 16 символів (комбінація літер, цифр, опційно спецсимволів).  
- Служить для генерації унікальних ліцензійних ключів для компаній.

### 1.2 Генерація ключів через майстер-бот
- Майстер-бот на твоєму сервері створює ключі через команду або інтерфейс.  
- Під час генерації можна вказати:
  - Назву компанії / сервера / користувача
  - Додаткову інформацію (опційно)  

### 1.3 Прив’язка ключа
- При першому запуску бота на сервері компанії ключ прив’язується до:
  - MAC-адреси мережевої карти
  - Серійних номерів ключових компонентів заліза (CPU, диск, RAM)
- Після прив’язки ключ не працює на іншому обладнанні.

### 1.4 Серверна перевірка
- При запуску бот робить HTTPS-запит на майстер-сервер:
  - Передає свій ліцензійний ключ
  - Передає hardware_id
- Сервер повертає `OK` або `BLOCK`.  
- Якщо ключ неправильний або використовується на іншому обладнанні – бот блокує роботу.

### 1.5 Моніторинг та повідомлення
- Мастер-бот веде журнал усіх запитів активації.  
- Telegram-бот на майстер-сервері повідомляє про:
  - Спроби запуску з неавторизованого обладнання  
  - Подвоєне використання ключа  
  - Помилки верифікації

### 1.6 Шифрування ключа
- Ключ зберігається зашифрованим на сервері компанії (AES-256).  
- Серверна комунікація здійснюється через RSA для безпечного обміну ключами.

## 2. Етапи розробки

### 2.1 Генерація Master Key
1. Майстер-бот створює мастер-ключ на твоєму сервері.  
2. Ключ зберігається у безпечному середовищі (наприклад, у зашифрованій базі або HashiCorp Vault).  

### 2.2 Генерація ліцензійних ключів для компаній
1. Вводяться параметри: назва компанії / сервера / користувача.  
2. Майстер-бот генерує унікальний 16-символьний ключ.  
3. Ключ зберігається у базі майстер-сервера разом з інформацією про компанію та hardware_id (після першого запуску).

### 2.3 Інтеграція перевірки в код бота
1. На старті бот відправляє запит на майстер-сервер:
   ```json
   {
     "key": "XXXX-XXXX-XXXX-XXXX",
     "hardware_id": "MAC+CPU+DISK"
   }
   ```
2. Сервер повертає `OK` або `BLOCK`.
3. Якщо `BLOCK` – бот зупиняє роботу та надсилає лог на сервер.

### 2.4 Прив’язка обладнання
1. Під час першого успішного запиту сервер зберігає `hardware_id`.
2. Будь-який наступний запит з іншим `hardware_id` буде відхилено.

### 2.5 Моніторинг
1. Мастер-бот веде журнал усіх активацій ключів.
2. Telegram-бот повідомляє про будь-які спроби несанкціонованого запуску.

---

## 3. Фінальний результат
- Мастер-бот дозволяє створювати ключі для будь-яких компаній самостійно.
- Кожен ключ прив’язується до конкретного серверного обладнання.
- Бот на сервері компанії не запускається без перевірки ключа.
- Розробник отримує повідомлення про будь-які спроби несанкціонованого запуску.
